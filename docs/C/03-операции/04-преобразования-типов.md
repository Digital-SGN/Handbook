# Преобразование типов

Когда в выражении встречаются значения разных типов, компилятор **неявно приводит** их к одному типу. То же самое происходит при присваивании: значение всегда подгоняется под тип переменной.

Пример:

```cpp
char c = 6;
int d = c;
```

Значение типа `char` присваивается переменной типа `int` — компилятор автоматически расширяет его до `int`.

Но не всякое преобразование безопасно: у разных типов разное внутреннее представление, и переход от одного к другому **не всегда проходит без потери данных**.

## Неявное преобразование в арифметике

Когда в одной операции участвуют операнды разных типов, компилятор действует по **правилам обычных арифметических преобразований**. Они проверяются по порядку сверху вниз, и первое подходящее правило срабатывает:

1. Если один из операндов — `long double`, второй приводится к `long double`.
2. Иначе если один — `double`, второй приводится к `double`.
3. Иначе если один — `float`, второй приводится к `float`.
4. Иначе если один — `unsigned long int`, второй приводится к `unsigned long int`.
5. Иначе если один — `long`, второй приводится к `long`.
6. Иначе если один — `unsigned`, второй приводится к `unsigned`.
7. Иначе оба операнда приводятся к `int`.

Смысл: **меньший тип расширяется до большего**. Так компилятор страхуется от потери данных.

Пример:

```cpp
#include <stdio.h>

int main(void)
{
    int number1 = 10;
    double number2 = 4;
    double result = number1 + number2;   // 14.000000

    printf("result = %f\n", result);
    return 0;
}
```

Здесь `number2` имеет тип `double`, поэтому `number1` автоматически расширяется до `double`. Результат сложения — тоже `double`.

> **Правило «большего брата»:** в арифметике побеждает тип с большей разрядностью и точностью. Целый операнд рядом с `double` станет `double`, рядом с `long` — `long` и т.д.

## Явное преобразование

Иногда нужно навязать свой тип — тогда используют **операцию преобразования** (casting):

```cpp
(тип) выражение
```

Пример с делением:

```cpp
#include <stdio.h>

int main(void)
{
    int a = 10;
    int b = 4;

    int c = a / b;                       // 2
    double d = a / b;                    // 2.000000
    double e = (double)a / (double)b;    // 2.500000

    printf("c = %d\n", c);
    printf("d = %f\n", d);
    printf("e = %f\n", e);
    return 0;
}
```

Разберём каждый случай:

| Выражение | Что происходит | Результат |
| :--- | :--- | :--- |
| `int c = a / b` | Оба операнда целые → целочисленное деление, остаток отбрасывается | `2` |
| `double d = a / b` | Сначала целочисленное деление (`2`), **потом** расширение до `double` | `2.000000` |
| `double e = (double)a / (double)b` | Оба операнда приводятся к `double` **до** деления | `2.500000` |

**Ключевой момент:** приведение типов нужно делать **до** операции, а не после. `(double)(a / b)` дало бы `2.0`, а не `2.5`, потому что деление уже прошло в целых числах.

### Явное преобразование к `char`

```cpp
#include <stdio.h>

int main(void)
{
    int number = 70;
    char symbol = (char) number;

    printf("symbol = %c\n", symbol);            // F
    printf("symbol (int code) = %d\n", symbol); // 70
    return 0;
}
```

Число `70` — это ASCII-код символа `F`. После приведения к `char` переменная хранит именно этот символ.

## Безопасные и опасные преобразования

Не всякое преобразование проходит без потерь. **Безопасными** (то есть без потери информации) считаются цепочки расширения:

```text
char → short → int → long
unsigned char → unsigned short → unsigned int → unsigned long
float → double → long double
```

Во всех остальных случаях возможна **потеря точности**:

- переход от большего типа к меньшему (например, `int` → `char`);
- переход от знакового к беззнаковому с потерей знака;
- переход от вещественного к целому (дробная часть отбрасывается).

> **Совет:** избегайте неявных сужающих преобразований. Если оно действительно нужно — ставьте явное приведение и комментарий: так видно, что потеря данных осознанная.

## Примеры потери данных

### Пример 1: `int` → `char`

```cpp
#include <stdio.h>

int main(void)
{
    int number1 = 300;
    char code = number1;   // неявное сужение — усечение до 1 байта

    printf("code = %d\n", code);   // 44
    return 0;
}
```

Почему `44`? Число `300` в двоичном виде:

```text
00000001 00101100
```

`char` занимает только 1 байт, поэтому остаётся младший байт:

```text
00101100
```

Это и есть `44` в десятичной системе.

### Пример 2: `int` → `short`

```cpp
#include <stdio.h>

int main(void)
{
    short number2 = 100000;   // неявное сужение — усечение до 2 байт

    printf("number2 = %d\n", number2);   // -31072
    return 0;
}
```

Число `100000` по умолчанию имеет тип `int` (4 байта). При присваивании переменной `short` (2 байта) старшие байты **отбрасываются**, и значение превращается в `−31072`.

Почему именно `−31072`? `100000` в двоичном виде:

```text
00000000 00000001 10000110 10100000
```

Младшие 2 байта:

```text
10000110 10100000
```

Старший бит равен `1` → число считается отрицательным. Переводим из дополнительного кода: `−31072`. Если тот же набор битов прочитать как `unsigned short`, получится `34464`.

> **Вывод:** преобразование «широкий → узкий» может не просто обрезать старшие биты, а **изменить знак** числа. Именно поэтому это опасное преобразование.

## Итог

- При смешивании типов в арифметике компилятор **неявно приводит** меньший тип к большему.
- Правила преобразования проверяются по порядку: от `long double` до `int`.
- **Явное приведение** — `(тип) выражение`. Оно нужно, когда тип не устраивает.
- Приведение делайте **до операции**: `(double)a / b`, а не `(double)(a / b)`.
- **Безопасные цепочки расширения:** `char → short → int → long`, `float → double → long double`.
- Все прочие преобразования **могут терять данные**: усечение старших битов, потеря знака, отбрасывание дробной части.
- Сужающие преобразования — с явным приведением и комментарием.
