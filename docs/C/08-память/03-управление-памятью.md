# Управление динамической памятью

Когда память выделена через `malloc`/`calloc`/`realloc`, мы получаем **указатель** на блок. Само выделение — половина дела. Вторая половина — понять, **когда** этот блок освобождать.

Область видимости указателя подсказывает ответ. Есть три типичных сценария:

1. указатель **локальный** — освобождать в конце блока;
2. указатель **статический** — освобождать один раз, при завершении использования;
3. указатель **глобальный** — освобождать по завершении работы с ним.

## Локальный указатель

Самый частый случай: указатель объявлен **внутри функции**. Память доступна только в этой функции — значит, освобождать нужно **до выхода**.

```cpp
#include <stdio.h>
#include <stdlib.h>

void createPointer(void)
{
    int *p = malloc(sizeof(int));

    if (p == NULL) {
        return;   // не удалось выделить — выходим
    }

    *p = 1;
    printf("%d\n", *p);

    free(p);      // конец блока — освобождаем
}

int main(void)
{
    createPointer();
    createPointer();
    createPointer();
    return 0;
}
```

Вывод:

```text
1
1
1
```

Что происходит:

1. `createPointer` вызывается три раза.
2. При каждом вызове `malloc` выделяет **новый** блок — память не переиспользуется автоматически.
3. После `printf` вызывается `free`, блок возвращается системе.
4. Указатель `p` — локальный, в момент выхода из функции он **исчезает**. Но память должна быть освобождена **до** этого — что и сделано.

Если `free(p)` убрать — каждый вызов будет оставлять 4 байта в куче. **Утечка памяти.**

## Указатель во вложенном блоке

То же самое работает для любого блока кода, не только для функции:

```cpp
#include <stdio.h>
#include <stdlib.h>

void createPointer(void)
{
    printf("Code block starts\n");
    {
        int *p = malloc(sizeof(int));
        if (p == NULL) {
            return;
        }

        *p = 1;
        printf("%d\n", *p);

        free(p);   // конец блока — освобождаем
    }
    printf("Code block ends\n");
}

int main(void)
{
    createPointer();
    return 0;
}
```

Указатель `p` существует только внутри `{ ... }`. Соответственно `free(p)` должен быть **тоже внутри** этого блока — после закрывающей скобки `p` уже не существует.

> **Правило:** память освобождается там же, где оканчивается **время жизни указателя**, через который вы к ней обращаетесь. Если указатель локальный — освобождайте в той же функции или блоке.

## Статический указатель

**Статический** указатель — объявлен с ключевым словом `static`. Он живёт **всю программу**, но доступен только из своей функции. Такой указатель удобен, когда блок нужно выделить **один раз** и переиспользовать.

```cpp
#include <stdio.h>
#include <stdlib.h>

int *createPointer(void)
{
    static int *p = NULL;

    if (p == NULL)
    {
        p = malloc(sizeof(int));
        if (p == NULL) {
            return NULL;
        }
        *p = 1;
    }

    printf("%d\n", *p);
    (*p)++;

    return p;
}

int main(void)
{
    int *ptr;

    ptr = createPointer();
    ptr = createPointer();
    ptr = createPointer();

    free(ptr);
    return 0;
}
```

Вывод:

```text
1
2
3
```

Разбор:

- `static int *p = NULL` — указатель инициализируется **один раз** при первом входе в функцию и сохраняется между вызовами;
- первый вызов: `p == NULL`, поэтому `malloc` выделяет блок, `*p = 1`, выводит `1`, увеличивает до `2`;
- второй вызов: `p != NULL` — память **не выделяется повторно**, выводит `2`, увеличивает до `3`;
- третий: выводит `3`, увеличивает до `4`.

Память освобождается **один раз** — в `main`, когда блок больше не нужен.

### Почему так делают

- избежать повторных `malloc` — выделение памяти небесплатно;
- сохранить состояние между вызовами;
- ленивая инициализация — блок создаётся при первом обращении.

### Опасность: указатель на освобождённую память

После `free(ptr)` в `main` указатель `p` **внутри функции всё ещё хранит старый адрес**. Если снова вызвать `createPointer()`, получим **use-after-free**:

```cpp
free(ptr);
ptr = createPointer();   // UB: p указывает на освобождённую память
```

Программа может «работать», а может упасть или вернуть мусор. Это **недетерминированное** поведение.

### Как правильно

Если блок освобождается снаружи, статический указатель нужно **обнулить**. Для этого добавьте функцию-«сброс»:

```cpp
void resetPointer(void)
{
    extern int *getStaticPointer(void);   // либо переделать через возврат
    // ...
}
```

На практике удобнее не отдавать владение наружу, а сделать пару функций:

```cpp
static int *p = NULL;

int *getPointer(void)
{
    if (p == NULL) {
        p = malloc(sizeof(int));
        if (p != NULL) *p = 1;
    }
    return p;
}

void releasePointer(void)
{
    free(p);
    p = NULL;   // ← важно: обнуляем статический указатель
}
```

Тогда `main` вызывает `releasePointer()`, а не `free(ptr)` напрямую.

> **Совет:** статический указатель — приём для узких задач. В большинстве случаев лучше вернуть обычный указатель и позволить вызывающей стороне управлять памятью. Иначе получается скрытое глобальное состояние, которое тяжело отлаживать.

## Глобальный указатель

**Глобальный** указатель объявлен вне функций. Он доступен **всем** функциям, объявленным ниже. Освобождать — когда работа с ним завершена.

```cpp
#include <stdio.h>
#include <stdlib.h>

int *p = NULL;   // глобальный указатель

void createPointer(void)
{
    printf("%d\n", *p);
    (*p)++;
}

int main(void)
{
    p = malloc(sizeof(int));
    if (p == NULL) {
        return 1;
    }
    *p = 1;

    createPointer();
    createPointer();
    createPointer();

    free(p);
    p = NULL;   // полезная привычка

    return 0;
}
```

Вывод:

```text
1
2
3
```

Разбор:

- `p` доступен и в `main`, и в `createPointer`;
- выделение и освобождение — в `main`;
- `createPointer` только читает и меняет значение.

### Проблемы глобальных указателей

- **Кто владеет памятью?** Если несколько функций могут её освободить — легко получить двойной `free`.
- **Кто её выделяет?** Если никто не выделил — разыменование `NULL`.
- **Порядок вызовов.** `createPointer` нельзя вызывать до `malloc` — упадёт.

Глобальные указатели удобны для маленьких программ, но **плохо масштабируются**. В больших проектах предпочитают:

- передавать указатель **как аргумент**;
- возвращать из функции;
- объединять данные и указатели в структуру-«контекст».

## Сводная таблица

| Тип указателя | Время жизни | Когда освобождать |
| :--- | :--- | :--- |
| **Локальный** | До выхода из функции/блока | В конце блока |
| **Статический** | Вся программа | При завершении использования, с обнулением |
| **Глобальный** | Вся программа | Когда данные больше не нужны |

## Что выбрать

**Локальный** — по умолчанию. Он предсказуем: где выделили, там и освободили.

**Статический** — если блок нужно создавать один раз при первом вызове и сохранять между вызовами. Но не отдавайте владение наружу без функции `release`.

**Глобальный** — только для маленьких программ или как временное решение. В большом коде он превращается в источник трудноуловимых багов.

> **Золотое правило:** память освобождает **тот, кто её выделил**. Если функция отдаёт указатель наружу, документируйте это явно — например, комментарием или в имени: `createPointer` возвращает, значит вызывающий должен освободить.

## Итог

- Область видимости указателя определяет, **где** нужно освобождать память.
- **Локальный** указатель — освобождаем в конце функции/блока. Иначе — утечка.
- **Статический** указатель живёт всю программу и хранит значение между вызовами. Освобождаем один раз, **обязательно обнуляя** указатель.
- **Глобальный** указатель доступен всем функциям. Освобождаем, когда данные больше не нужны.
- После `free` **всегда** ставьте `ptr = NULL` — это защищает от use-after-free и двойного `free`.
- Память освобождает **тот, кто её выделил**. Это правило стоит соблюдать, чтобы не путаться во владении.
- Статические и глобальные указатели — источник скрытого состояния. Используйте их осознанно.
