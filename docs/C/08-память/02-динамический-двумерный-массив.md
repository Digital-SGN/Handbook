# Динамический двумерный массив

Двумерный массив можно выделить **динамически** — когда количество строк и столбцов становится известно во время выполнения. Более того, можно сделать **зубчатый массив** (jagged array): у каждой строки своё количество столбцов.

## Идея: массив указателей

Динамический двумерный массив строится в **два уровня**:

1. **Массив указателей** — по одному указателю на каждую строку.
2. **Каждая строка** — отдельный массив `int`.

Тип верхнего уровня: **`int **`** — «указатель на указатель на `int`».

Разберём по частям:

- `int **table` — `table` хранит адрес массива указателей;
- `table[i]` — `i`-й указатель, адрес строки `i`;
- `table[i][j]` — элемент в строке `i`, столбце `j`.

То же самое через операторы:

```cpp
table[i][j]   ==   *(*(table + i) + j)
```

## Схема памяти

```text
table ──► ┌───────────┐
          │ table[0]  │ ──► ┌────┬────┬────┐
          ├───────────┤     │ 1  │ 2  │ 3  │   (3 столбца)
          │ table[1]  │ ──► ├────┼────┤
          ├───────────┤     │ 4  │ 5  │         (2 столбца)
          │ table[2]  │ ──► ...
          └───────────┘
```

- `table` — массив из `rowscount` указателей;
- каждая `table[i]` — отдельный блок памяти размером `rows[i] * sizeof(int)`.

Именно поэтому строки могут иметь **разную длину**: они живут в разных блоках и не связаны друг с другом.

## Полный пример

Программа запрашивает количество строк, потом для каждой строки — количество столбцов и значения.

```cpp
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int **table;      // указатель на массив указателей
    int *rows;        // количество столбцов для каждой строки
    int rowscount;    // количество строк

    printf("Rows count: ");
    if (scanf("%d", &rowscount) != 1 || rowscount <= 0) {
        printf("Некорректный ввод\n");
        return 1;
    }

    // 1. Массив указателей на строки
    table = calloc(rowscount, sizeof(int *));
    if (table == NULL) {
        printf("Не удалось выделить память\n");
        return 1;
    }

    // 2. Массив с количеством столбцов для каждой строки
    rows = malloc(rowscount * sizeof(int));
    if (rows == NULL) {
        free(table);
        printf("Не удалось выделить память\n");
        return 1;
    }

    // 3. Для каждой строки — свой размер и значения
    for (int i = 0; i < rowscount; i++)
    {
        printf("Columns count for row %d: ", i);
        if (scanf("%d", &rows[i]) != 1 || rows[i] <= 0) {
            printf("Некорректный ввод\n");
            rows[i] = 0;
            continue;
        }

        table[i] = calloc(rows[i], sizeof(int));
        if (table[i] == NULL) {
            printf("Не удалось выделить память для строки %d\n", i);
            rows[i] = 0;
            continue;
        }

        for (int j = 0; j < rows[i]; j++)
        {
            printf("table[%d][%d] = ", i, j);
            scanf("%d", &table[i][j]);
        }
    }

    // 4. Вывод
    printf("\nResult:\n");
    for (int i = 0; i < rowscount; i++)
    {
        for (int j = 0; j < rows[i]; j++)
        {
            printf("%d\t", table[i][j]);
        }
        printf("\n");
    }

    // 5. Освобождение памяти — после вывода, а не во время
    for (int i = 0; i < rowscount; i++)
    {
        free(table[i]);
    }
    free(table);
    free(rows);

    return 0;
}
```

Пример работы:

```text
Rows count: 2
Columns count for row 0: 3
table[0][0] = 1
table[0][1] = 2
table[0][2] = 3
Columns count for row 1: 2
table[1][0] = 4
table[1][1] = 5

Result:
1       2       3
4       5
```

## Освобождение памяти

Порядок освобождения **обратен** порядку выделения:

1. Сначала — **каждая строка** отдельно: `free(table[i])`.
2. Потом — **массив указателей**: `free(table)`.
3. Затем — **вспомогательный массив**: `free(rows)`.

```cpp
for (int i = 0; i < rowscount; i++)
{
    free(table[i]);
}
free(table);
free(rows);
```

### Что будет, если перепутать порядок

Если сначала `free(table)`, а потом пытаться `free(table[i])` — вы обратитесь к освобождённой памяти. Это **use-after-free**, то есть неопределённое поведение.

### Частая ошибка: освобождение внутри вывода

В исходном примере Метанита `free(table[i])` стоял **внутри цикла вывода**:

```cpp
for (int i = 0; i < rowscount; i++)
{
    for (int j = 0; j < rows[i]; j++)
    {
        printf("%d\t", table[i][j]);
    }
    free(table[i]);   // ← плохо: массив разрушается по ходу
}
```

Это работает только потому, что после вывода строки мы к ней больше не возвращаемся. Но если понадобится второй проход — данных уже не будет. **Освобождайте память после того, как закончили с данными.**

### Про `rows[i]` при ошибке

Если `calloc` для строки `i` не удался, в `rows[i]` останется прежнее значение — но `table[i]` будет `NULL`. При освобождении `free(NULL)` — безопасно, так что цикл `free(table[i])` не упадёт. Но при выводе такого массива можно получить мусор — поэтому в примере выше мы ставим `rows[i] = 0` при ошибке.

## Альтернатива: плоский массив

Зубчатый массив **гибок**, но у него есть цена:

- **много выделений памяти** — по одному `malloc` на каждую строку;
- **плохая локальность** — строки разбросаны по куче, кэш процессора работает хуже;
- **сложнее освобождать**.

Если строки **одинаковой длины** (обычная матрица `N × M`), лучше выделить **один плоский блок** и индексировать его вручную:

```cpp
int n = 5, m = 7;
int *matrix = malloc(n * m * sizeof(int));

if (matrix != NULL)
{
    // доступ к элементу (i, j)
    for (int i = 0; i < n; i++)
    {
        for (int j = 0; j < m; j++)
        {
            matrix[i * m + j] = 0;
        }
    }

    free(matrix);   // одно освобождение вместо n + 1
}
```

Преимущества:

- **одно выделение** и одно освобождение;
- данные лежат **подряд** — быстрее;
- легко передавать в функции.

Недостаток: строки одинаковой длины. Для «настоящего» зубчатого массива нужен `int **`.

### Что выбрать

| Ситуация | Решение |
| :--- | :--- |
| Прямоугольная матрица | Плоский массив |
| Строки разной длины | `int **` (зубчатый) |
| Часто добавляются/удаляются строки | `int **` |
| Важна производительность | Плоский массив |

## Итог

- Динамический двумерный массив строится в **два уровня**: массив указателей + строки.
- Верхний уровень — **`int **`** (указатель на указатель).
- Зубчатый массив позволяет каждой строке иметь **свой размер**.
- **Освобождение** — в обратном порядке: сначала строки, потом массив указателей.
- Освобождать память **после** работы с данными, а не в процессе.
- Для прямоугольных матриц **плоский массив** проще и быстрее.
- Всегда **проверяйте `NULL`** после каждого `malloc`/`calloc`.
