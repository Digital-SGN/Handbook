# Арифметика указателей

К указателям применимы арифметические операции: сложение, вычитание, инкремент, декремент. Но работают они **не так, как с числами**: результат зависит от **типа указателя**.

Доступны три вида операций:

- `ptr + n` — сдвиг вперёд на `n` объектов типа;
- `ptr - n` — сдвиг назад на `n` объектов;
- `ptr2 - ptr1` — «расстояние» между указателями в объектах.

## Инкремент и декремент

```cpp
#include <stdio.h>

int main(void)
{
    int n = 10;
    int *ptr = &n;

    printf("address=%p\tvalue=%d\n", (void *)ptr, *ptr);

    ptr++;
    printf("address=%p\tvalue=%d\n", (void *)ptr, *ptr);

    ptr--;
    printf("address=%p\tvalue=%d\n", (void *)ptr, *ptr);

    return 0;
}
```

Пример вывода:

```text
address=0x7ffd4a3b2c4c   value=10
address=0x7ffd4a3b2c50   value=6356652
address=0x7ffd4a3b2c4c   value=10
```

Адрес **увеличился на 4**, потому что размер `int` — 4 байта. Инкремент указателя на `int` сдвигает его не на 1 байт, а на **размер одного объекта типа**.

### Общее правило

```text
ptr + n  ⟶  адрес увеличивается на  n × sizeof(*ptr)  байт
ptr - n  ⟶  адрес уменьшается на     n × sizeof(*ptr)  байт
```

| Тип указателя | Размер объекта | `ptr++` сдвигает на |
| :--- | :---: | :---: |
| `char *` | 1 байт | 1 байт |
| `short *` | 2 байта | 2 байта |
| `int *` | 4 байта | 4 байта |
| `double *` | 8 байт | 8 байт |

Смысл операции: «перейти к **следующему объекту** в памяти». Не к следующему байту.

### Пример с разными типами

```cpp
#include <stdio.h>

int main(void)
{
    double d = 10.6;
    double *pd = &d;
    printf("pd: %p\n", (void *)pd);
    pd++;
    printf("pd: %p\n", (void *)pd);

    char c = 'N';
    char *pc = &c;
    printf("pc: %p\n", (void *)pc);
    pc++;
    printf("pc: %p\n", (void *)pc);

    return 0;
}
```

```text
pd: 0x7ffd4a3b2c48
pd: 0x7ffd4a3b2c50   ← +8 (размер double)
pc: 0x7ffd4a3b2c47
pc: 0x7ffd4a3b2c48   ← +1 (размер char)
```

> **Важно:** сдвигать указатель за пределы «своего» объекта — **неопределённое поведение**. Если указатель указывает на **одиночную** переменную `int`, то `ptr++` формально запрещён. Пример выше работает «случайно» — он попал в соседнюю память, значение оттуда читать нельзя. Арифметика указателей корректна только **внутри одного массива** или блока памяти.

## Сложение и вычитание числа

То же правило работает и с числами, отличными от единицы:

```cpp
#include <stdio.h>

int main(void)
{
    double d = 10.6;
    double *pd = &d;
    printf("pd: %p\n", (void *)pd);

    pd = pd + 2;    // сдвиг вперёд на 2 объекта double (2 × 8 = 16 байт)
    printf("pd: %p\n", (void *)pd);

    char c = 'N';
    char *pc = &c;
    printf("pc: %p\n", (void *)pc);

    pc = pc - 3;    // сдвиг назад на 3 объекта char (3 × 1 = 3 байта)
    printf("pc: %p\n", (void *)pc);

    return 0;
}
```

```text
pd: 0x7ffd4a3b2c48
pd: 0x7ffd4a3b2c58   ← +16 байт
pc: 0x7ffd4a3b2c47
pc: 0x7ffd4a3b2c44   ← −3 байта
```

Сложение и вычитание работают **только** с целочисленными операндами: `double * + int`, а не `double * + double *`. И нельзя умножать или делить указатели.

## Разность двух указателей

Из одного указателя можно вычесть другой — получится **расстояние** между ними в **объектах** типа указателя, а не в байтах.

```cpp
#include <stdio.h>
#include <stddef.h>

int main(void)
{
    int a = 10;
    int b = 23;
    int *pa = &a;
    int *pb = &b;

    ptrdiff_t c = pa - pb;

    printf("pa = %p\n", (void *)pa);
    printf("pb = %p\n", (void *)pb);
    printf("c = %td\n", c);

    return 0;
}
```

Пример вывода:

```text
pa = 0x7ffd4a3b2c48
pb = 0x7ffd4a3b2c44
c = 1
```

Адреса отличаются на 4 байта, но результат — `1`, потому что расстояние считается **в элементах `int`**: `4 / 4 = 1`.

### Тип ptrdiff_t

Результат вычитания указателей имеет тип **`ptrdiff_t`** — знаковый целочисленный тип, определённый в `<stddef.h>`. На 64-разрядных системах обычно совпадает с `long` и занимает 8 байт.

> **Для вывода `ptrdiff_t` используйте `%td`.** Спецификатор `%lld` может сработать, если `ptrdiff_t` определён как `long long`, но это не гарантировано стандартом. `%td` — переносимый вариант.

### Пример с массивом

```cpp
#include <stdio.h>
#include <stddef.h>

int main(void)
{
    int arr[64];
    int *ptr1 = &arr[10];
    int *ptr2 = &arr[40];

    ptrdiff_t dist = ptr2 - ptr1;   // 30

    printf("dist = %td\n", dist);
    return 0;
}
```

Указатели указывают на 10-й и 40-й элементы массива. Разница — `30` элементов `int`. Чтобы получить расстояние **в байтах**, умножьте на размер одного элемента:

```cpp
ptrdiff_t bytes = dist * sizeof(int);   // 30 × 4 = 120 байт
```

### Правило

Разность указателей имеет смысл только если оба указывают в **один и тот же массив** (или блок памяти). Иначе результат не определён.

## Указатель и значение: что меняется

Важно различать: изменяем мы **указатель** или **значение по адресу**, на который он указывает.

```cpp
int a = 10;
int *pa = &a;

int b = *pa + 20;   // работаем со ЗНАЧЕНИЕМ (10 + 20 = 30)
pa++;               // меняем сам УКАЗАТЕЛЬ

printf("b = %d\n", b);   // 30
```

- `*pa` — это число (`10`). `*pa + 20` — обычное сложение двух чисел.
- `pa++` — операция над самим указателем, значение `a` не меняется.

## Приоритет `*`, `++`, `--`

Операции `*`, `++`, `--` имеют **одинаковый приоритет** и выполняются **справа налево**, если стоят рядом. Это приводит к коварным выражениям.

### `*pa++`

```cpp
int a = 10;
int *pa = &a;

int b = *pa++;   // инкремент УКАЗАТЕЛЯ, потом разыменование
```

Порядок:

1. Постфиксный `++` применяется к `pa` — указатель сдвигается;
2. Но постфиксная форма возвращает **старое** значение;
3. Разыменование берёт значение по **старому** адресу — то есть `10`;
4. `b` получает `10`.

Вывод:

```text
pa: address=0x...a4   value=10
b: value=10
pa: address=0x...a8   value=6356648   ← указатель сдвинулся
```

### `(*pa)++`

Скобки меняют смысл:

```cpp
int b = (*pa)++;
```

Порядок:

1. `*pa` — получаем **значение** `10`;
2. `++` применяется к значению — оно становится `11`;
3. Постфиксная форма возвращает **старое** значение — `10`;
4. `b` получает `10`, но `a` теперь `11`.

Вывод:

```text
pa: address=0x...a4   value=10   ← адрес не изменился
b: value=10
pa: address=0x...a4   value=11   ← значение выросло
```

### `++*pa`

```cpp
int b = ++*pa;
```

Порядок:

1. `*pa` — значение `10`;
2. Префиксный `++` увеличивает его до `11`;
3. Возвращается **новое** значение — `11`;
4. `b` получает `11`, `a` тоже `11`.

### `*++pa`

```cpp
int b = *++pa;
```

Порядок:

1. Префиксный `++` сдвигает **указатель**;
2. Разыменование берёт значение по **новому** адресу;
3. Такого объекта может не быть — значение неопределено.

### Сводная таблица

| Выражение | Что меняется | Что возвращает |
| :--- | :--- | :--- |
| `*pa++` | указатель | старое значение по старому адресу |
| `(*pa)++` | значение | старое значение |
| `++*pa` | значение | новое значение |
| `*++pa` | указатель | значение по новому адресу |

> **Совет:** не пишите такие выражения. Разбейте на две строки — читать будет гораздо проще:
> ```cpp
> int b = *pa;
> pa++;
> ```

## Арифметика `void *`

**`void`** — неполный тип: компилятор не знает его размер. Поэтому формально **арифметика `void *` не определена стандартом**.

```cpp
#include <stdio.h>

int main(void)
{
    int num1 = 11;
    int num2 = 12;
    int num3 = 13;
    int num4 = 14;

    void *p_num = &num1;
    printf("*p_num: %d\n", *(int *)(p_num + 8));

    return 0;
}
```

GCC и Clang считают размер `void` равным **1 байту**, поэтому `p_num + 8` сдвинет указатель на 8 байт — а это адрес `num3`. Программа выведет:

```text
*p_num: 13
```

Но с флагом `-pedantic` компилятор предупредит:

```text
warning: pointer of type 'void *' used in arithmetic [-Wpointer-arith]
```

### Как правильно

Сначала приведите `void *` к конкретному типу, **затем** выполняйте арифметику:

```cpp
printf("*p_num: %d\n", *(((int *)p_num) + 2));
```

Здесь:

1. `(int *)p_num` — приводим `void *` к `int *`;
2. `+ 2` — сдвигаем на 2 объекта `int` (8 байт);
3. `*` — разыменовываем.

Это переносимо и не зависит от того, как компилятор трактует размер `void`.

> **Правило:** не выполняйте арифметику над `void *`. Приведите к конкретному типу — потом сдвигайте.

## Практическое применение

Арифметика указателей — не экзотика. Это **основа** работы с массивами в C.

### Обход массива через указатель

```cpp
#include <stdio.h>

int main(void)
{
    int arr[] = {10, 20, 30, 40, 50};
    size_t n = sizeof(arr) / sizeof(arr[0]);

    // через индекс
    for (size_t i = 0; i < n; i++)
    {
        printf("%d ", arr[i]);
    }
    printf("\n");

    // через указатель — то же самое
    for (int *p = arr; p < arr + n; p++)
    {
        printf("%d ", *p);
    }
    printf("\n");

    return 0;
}
```

`arr[i]` и `*(arr + i)` — **эквивалентные записи**. Это не совпадение, а определение языка: индексная запись — синтаксический сахар для арифметики указателей.

### Адрес элемента

```cpp
int arr[] = {10, 20, 30};

int *p0 = &arr[0];   // адрес первого
int *p1 = &arr[1];   // адрес второго
int *p2 = &arr[2];   // адрес третьего

// всё это — одно и то же:
arr       == &arr[0]
arr + 1   == &arr[1]
arr + 2   == &arr[2]
*(arr+1)  == arr[1]
```

Именно поэтому имя массива в функциях «превращается» в указатель — но об этом в главе про функции.

## Итог

- `ptr + n` сдвигает указатель на `n × sizeof(*ptr)` байт — то есть на `n` **объектов**, а не байт.
- Размер сдвига зависит от **типа** указателя: `char *` — 1, `int *` — 4, `double *` — 8.
- Разность указателей даёт **расстояние в объектах**, результат имеет тип **`ptrdiff_t`**, выводится через **`%td`**.
- Арифметика корректна только **внутри одного массива**. Сдвиг за его границы — UB.
- `*pa++`, `(*pa)++`, `++*pa`, `*++pa` — четыре разных выражения. Не пишите их без скобок.
- Арифметика над **`void *`** формально не определена — сначала приводите к конкретному типу.
- `arr[i]` и `*(arr + i)` — **одно и то же**. Индексация — это арифметика указателей.
