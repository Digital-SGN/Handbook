# Препроцессор

**Препроцессор** — первая ступень компиляции. Он обрабатывает исходный текст **до** компиляции: подключает файлы, подставляет макросы, включает или отключает куски кода по условию.

Компиляция программы на C состоит из трёх этапов:

1. **Препроцессирование** — обработка директив `#`.
2. **Компиляция** — превращение в объектный файл.
3. **Линковка** — объединение объектных файлов в исполняемый файл.

Результат работы препроцессора — полный текст программы, в котором уже нет директив `#`. Его и получает компилятор.

## Директивы

Каждая директива начинается с `#` и располагается на **отдельной строке**. Директивы не завершаются точкой с запятой.

| Директива | Что делает |
| :--- | :--- |
| `#include` | Включает текст из файла |
| `#define` | Определяет макрос или константу |
| `#undef` | Отменяет определение |
| `#if` / `#elif` / `#else` / `#endif` | Условная компиляция |
| `#ifdef` / `#ifndef` | Проверка, определён ли макрос |
| `#error` | Останавливает компиляцию с сообщением |
| `#pragma` | Реализация-зависимые указания |
| `#line` | Меняет номер следующей строки |

## `#include`

Две формы:

```cpp
#include <stdio.h>     // из системных каталогов
#include "myheader.h"  // сначала из текущей папки
```

- **Угловые скобки** `<...>` — поиск в **системных** каталогах (стандартные заголовки, библиотеки).
- **Кавычки** `"..."` — сначала в текущей папке, потом в системных.

### Что можно включать

- Стандартные заголовки (`<stdio.h>`, `<stdlib.h>`, `<string.h>`, ...).
- Собственные заголовки `"myheader.h"` — **это правильно**.
- `.cpp` файлы через `#include` — **плохая практика**. Так можно, GCC это позволяет, но получается каша: код компилируется дважды, легко получить дубли символов. Для больших проектов используйте сборку из нескольких `.cpp` файлов (см. главу про модульное программирование).

## `#define`: константы

Простейшая форма — подстановка значения:

```cpp
#define PI 3.14159
#define MAX_SIZE 1024

double area = PI * r * r;
int arr[MAX_SIZE];
```

Препроцессор **текстово** заменит `PI` на `3.14159` **до компиляции**.

### Особенности

- Нет точки с запятой в конце. `#define PI 3.14;` — плохо: точка с запятой тоже подставится.
- Нет проверки типов.
- Нет области видимости — действует от места определения до конца файла.

> **Макрос vs `const`.** Для констант **предпочитайте `const`**:
> ```cpp
> const double PI = 3.14159;
> ```
> Компилятор видит тип, ловит ошибки, работает отладчик. `#define` оставьте для случаев, где `const` не работает (например, размер статического массива в C до C99).

## `#define`: макросы

Функциональные макросы принимают аргументы:

```cpp
#define MAX(a, b) ((a) > (b) ? (a) : (b))
#define SQUARE(x) ((x) * (x))
#define MIN(a, b) ((a) < (b) ? (a) : (b))
```

Использование:

```cpp
int m = MAX(3, 5);       // 5
int s = SQUARE(4);       // 16
```

### Скобки обязательны

Без скобок получится не то:

```cpp
#define SQUARE(x) x * x
int s = SQUARE(1 + 2);   // 1 + 2 * 1 + 2 = 5, а не 9
```

Скобки вокруг аргумента и вокруг всего выражения — **обязательны**:

```cpp
#define SQUARE(x) ((x) * (x))   // правильно
```

### Многострочные макросы

Каждая строка кроме последней заканчивается `\`:

```cpp
#define SWAP(a, b) do { \
    typeof(a) tmp = (a); \
    (a) = (b); \
    (b) = tmp; \
} while (0)
```

Обёртка `do { ... } while (0)` — стандартный приём: позволяет использовать макрос как обычную инструкцию с `;` в конце, и при этом не ломает `if` без скобок.

## Include guards

Если заголовочный файл подключается дважды (например, через два других заголовка), компилятор получит **двойное определение** и выдаст ошибку. Решение — **include guards**:

```cpp
#ifndef MYHEADER_H
#define MYHEADER_H

// содержимое файла

#endif
```

Как это работает:

- `#ifndef MYHEADER_H` — «если `MYHEADER_H` ещё не определён»;
- `#define MYHEADER_H` — «определим его сейчас»;
- при повторном `#include` макрос уже есть — всё содержимое **пропускается**.

Имя макроса выбирают в стиле `ИМЯ_ФАЙЛА_H`, заглавными буквами.

### `#pragma once`

Многие компиляторы поддерживают альтернативу:

```cpp
#pragma once
```

Коротко, работает в GCC, Clang, MSVC. **Но не входит в стандарт C.** Для переносимости — используйте include guards.

## Условная компиляция

Позволяет **исключать** куски кода до компиляции:

```cpp
#ifdef DEBUG
    printf("Отладочная информация\n");
#endif
```

- `#ifdef X` — если `X` определён;
- `#ifndef X` — если **не** определён;
- `#if` — по значению выражения.

### `#if` с выражениями

```cpp
#if VERSION >= 2
    do_something_new();
#else
    do_something_old();
#endif
```

### `#elif`

```cpp
#if defined(_WIN32)
    // Windows
#elif defined(__linux__)
    // Linux
#elif defined(__APPLE__)
    // macOS
#else
    #error "Unsupported platform"
#endif
```

`defined(X)` — то же самое, что `#ifdef X`, но можно комбинировать с логикой: `#if defined(X) && !defined(Y)`.

### `#error`

Останавливает компиляцию:

```cpp
#if !defined(_WIN32) && !defined(__linux__) && !defined(__APPLE__)
    #error "Unsupported platform"
#endif
```

### `#undef`

Отменяет определение:

```cpp
#undef PI
```

Полезно перед переопределением макроса или для ограничения его действия.

## Предопределённые макросы

Компилятор определяет их сам. Основные:

| Макрос | Значение |
| :--- | :--- |
| `__FILE__` | Имя текущего файла (строка) |
| `__LINE__` | Номер текущей строки |
| `__DATE__` | Дата компиляции |
| `__TIME__` | Время компиляции |
| `__func__` | Имя текущей функции (C99) |
| `__STDC__` | `1`, если компилятор соответствует стандарту |
| `__STDC_VERSION__` | Версия стандарта (`199901L`, `201112L`, ...) |

### Применение: отладочный вывод

```cpp
#define LOG(msg) \
    printf("[%s:%d] %s\n", __FILE__, __LINE__, msg)

LOG("Something happened");
// [main.cpp:42] Something happened
```

Это очень полезно: сразу видно, где произошло событие, без ручного написания имени файла.

## Операторы `#` и `##`

### `#` — превратить в строку

```cpp
#define STR(x) #x

printf("%s\n", STR(Hello));   // Hello
printf("%s\n", STR(1 + 2));   // 1 + 2
```

`#x` берёт **текст аргумента** и оборачивает его в кавычки.

### `##` — склеить токены

```cpp
#define CONCAT(a, b) a##b

int xy = 10;
int xyz = CONCAT(x, y);   // то же самое, что xy = 10
```

`a##b` склеивает два токена в один: `x` и `y` → `xy`.

> **Осторожно.** Склеивание — тонкий инструмент, применять редко. Хорошая практика — использовать его только когда действительно нельзя обойтись (метапрограммирование, генерация имён функций).

## Опасности макросов

### 1. Побочные эффекты

```cpp
#define SQUARE(x) ((x) * (x))

int i = 5;
int s = SQUARE(i++);   // i++ вычисляется ДВАЖДЫ!
```

Раскроется в `((i++) * (i++))` — `i` увеличится на 2, результат непредсказуем.

**Решение:** никогда не передавайте в макросы выражения с побочными эффектами (`++`, `--`, вызовы функций). Или используйте `inline`-функции.

### 2. Раздувание кода

Макрос подставляется **в каждое место**, где используется. Крупный макрос в цикле — сотни копий кода в бинарнике.

### 3. Нет отладки

Отладчик видит уже развёрнутый код. Поставить точку останова внутрь макроса нельзя.

### 4. Нет проверки типов

`MAX("abc", 5)` скомпилируется без ошибок — но результат будет мусором.

> **Совет:** используйте `inline`-функции вместо функциональных макросов везде, где возможно:
> ```cpp
> static inline int max_int(int a, int b) {
>     return a > b ? a : b;
> }
> ```
> Компилятор сам встроит её в место вызова, но при этом вы получите типы, отладку и отсутствие побочных эффектов.

## Итог

- **Препроцессор** работает **до** компилятора: `#include`, `#define`, условная компиляция.
- `#include <...>` — системные заголовки, `#include "..."` — свои.
- **Не включайте `.c` файлы** через `#include` — это плохая практика.
- `#define` для констант → лучше `const`. `#define` для функций → лучше `inline`.
- **Include guards** (`#ifndef` + `#define` + `#endif`) — обязательны для заголовков.
- `#ifdef` / `#if` / `#elif` / `#else` / `#endif` — условная компиляция.
- **Предопределённые макросы:** `__FILE__`, `__LINE__`, `__func__`, `__DATE__` — полезны для логов.
- `#` — превращает аргумент в строку, `##` — склеивает токены.
- **У макросов много ловушек** — используйте их осторожно, а лучше заменяйте функциями.
