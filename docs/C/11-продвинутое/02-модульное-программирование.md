# Модульное программирование

Пока программа маленькая, её можно держать в одном файле. Но рано или поздно файл перерастает сотни строк, и работать с ним становится тяжело. **Модульное программирование** решает эту проблему: код разбивается на **модули** — независимые части, каждая со своей зоной ответственности.

## Зачем разбивать код

Один файл на 5000 строк — это боль:

- тяжело ориентироваться;
- любое изменение затрагивает всех;
- невозможно переиспользовать часть кода в другом проекте;
- параллельная работа нескольких разработчиков превращается в конфликт правок.

**Модуль** — это логически связанная часть программы: например, «работа с точками на плоскости», «парсинг JSON», «работа с датами». Каждый модуль живёт в своих файлах и общается с другими через **заголовок**.

## Модуль = `.h` + `.c`

В C модуль обычно состоит из **двух файлов**:

- **`module.h`** — **заголовок**: что модуль предоставляет. Прототипы функций, объявления типов, константы.
- **`module.c`** — **реализация**: как это работает. Тела функций, вспомогательные детали.

Правило, которое стоит запомнить:

> **В `.h` — что видно снаружи. В `.c` — как это устроено.**

Заголовок — это **публичный интерфейс** модуля. Всё, что там не объявлено, для остальных файлов **не существует**.

## Что писать в `.h`, что в `.c`

### В `.h`

- Прототипы функций, доступных снаружи.
- Определения `struct`, `enum`, `union` (если они видны пользователю).
- `typedef`.
- Константы через `#define` или `static const`.
- Макросы.

### В `.c`

- Тела функций.
- **Локальные** функции (не видны снаружи).
- Локальные переменные и типы.
- Вспомогательные функции и константы.

### Чего **не должно** быть в `.h`

- **Определений** функций (тела) — иначе при подключении в нескольких `.c` получите ошибку «multiple definition».
- **Определений** переменных — глобальная переменная с инициализацией в `.h` тоже даст duplicate.
- `#include` того, что не нужно тем, кто подключает заголовок. Держите зависимости минимальными.

## Пример: модуль `point`

Разберём простой модуль для работы с точкой на плоскости.

### `point.h`

```cpp
#ifndef POINT_H
#define POINT_H

typedef struct {
    double x;
    double y;
} point;

// создаёт точку с заданными координатами
point point_make(double x, double y);

// складывает две точки покоординатно
point point_add(point a, point b);

// вычисляет расстояние между двумя точками
double point_distance(point a, point b);

// выводит точку в формате "(x, y)"
void point_print(const point *p);

#endif
```

### `point.c`

```cpp
#include "point.h"
#include <stdio.h>
#include <math.h>

point point_make(double x, double y)
{
    point p = { x, y };
    return p;
}

point point_add(point a, point b)
{
    return point_make(a.x + b.x, a.y + b.y);
}

double point_distance(point a, point b)
{
    double dx = a.x - b.x;
    double dy = a.y - b.y;
    return sqrt(dx * dx + dy * dy);
}

void point_print(const point *p)
{
    printf("(%.2f, %.2f)\n", p->x, p->y);
}
```

Обратите внимание: `.c` включает **свой же** заголовок. Это гарантирует, что прототипы и определения совпадают.

### `main.c`

```cpp
#include <stdio.h>
#include "point.h"

int main(void)
{
    point a = point_make(0, 0);
    point b = point_make(3, 4);

    printf("Distance: %.2f\n", point_distance(a, b));

    point c = point_add(a, b);
    point_print(&c);

    return 0;
}
```

### Что произошло

- `main.c` **не знает**, как устроен `point` внутри. Он видит только прототипы из `point.h`.
- Можно полностью переписать `point.c`, не меняя `main.c` — лишь бы прототипы остались те же.
- Модуль можно **переиспользовать** в другом проекте: скопировать `point.h` и `point.c`.

## Include guards

В `point.h` в начале и конце стоит **include guard**:

```cpp
#ifndef POINT_H
#define POINT_H
// ...
#endif
```

Это **обязательно** для любого заголовка. Если один и тот же заголовок попадёт в один `.c` дважды (например, через два других заголовка) — компилятор получит **двойные определения** и упадёт с ошибкой.

Include guard говорит: «если уже подключён — пропусти этот блок».

Имя макроса — заглавными буквами, совпадает с именем файла. Для `point.h` — `POINT_H`.

Альтернатива — `#pragma once` в первой строке:

```cpp
#pragma once
```

## `static` в модулях

Ключевое слово `static` на уровне файла делает объект **невидимым для других модулей**.

### `static`-функция

```cpp
// point.c

static double square(double x)   // видна только в этом .c
{
    return x * x;
}

double point_distance(point a, point b)
{
    return sqrt(square(a.x - b.x) + square(a.y - b.y));
}
```

Функция `square` есть только внутри `point.c`. Из `main.c` её не видно — при попытке вызвать будет ошибка «implicit declaration».

### Зачем

- **Инкапсуляция**: внутренние детали не утекают наружу.
- **Избежание конфликтов**: если в другом модуле тоже есть `square`, конфликта не будет.
- **Оптимизация**: компилятор знает, что функцию не вызовут извне, и может её встроить.

### `static`-переменная

```cpp
// counter.c

static int counter = 0;   // видна только в этом .c

void counter_increment(void)
{
    counter++;
}

int counter_get(void)
{
    return counter;
}
```

Глобальная переменная `counter` скрыта от других модулей. Работать с ней можно только через функции. Это **безопаснее**, чем открытая глобальная переменная.

## Правила хорошего модуля

**1. Один модуль — одна задача.**  
Модуль `point` делает точки. Не кладите туда ещё и работу с файлами.

**2. Минимальный интерфейс.**  
В `.h` только то, что **действительно** нужно снаружи. Всё внутреннее — `static` в `.c`.

**3. Свой заголовок — включать первым.**  
В `.c` первая строка — `#include "module.h"`. Это гарантирует, что `.h` самодостаточен и совпадает с реализацией.

**4. Зависимости — явно.**  
Если модулю нужен `<math.h>`, включайте его в `.c`, а не полагайтесь, что кто-то включит раньше.

**5. Один `.h` может подключаться во многих `.c`.**  
Но каждый `.c` компилируется **отдельно** и включается в проект один раз.

**6. Префиксы функций.**  
Если модуль называется `point`, называйте функции `point_make`, `point_add`, `point_distance`. Так они не конфликтуют с другими модулями.

```cpp
point_make()      // хорошо: понятно, откуда
make()            // плохо: слишком общее имя
```

**7. Не включайте `.c` через `#include`.**  
Только `.h` файлы — отдельные единицы компиляции.

## Итог

- **Модуль** — логически связанная часть программы. Обычно `.h` + `.c`.
- **`.h`** — публичный интерфейс: прототипы, типы, константы.
- **`.c`** — реализация: тела функций, внутренние детали.
- В `.h` **нельзя**: определения функций, определения глобальных переменных.
- **`static`** делает функции и переменные **невидимыми** для других модулей.
- **Один модуль — одна задача.** Минимальный интерфейс, максимум `static` внутри.
- **Префиксы** (`point_`, `json_`) — чтобы имена не конфликтовали.
- Не включайте `.c` файлы через `#include` — только `.h`.
