# Поиск подстроки

Задача точного поиска подстроки звучит просто: дан текст `T` длины `n` и образец (шаблон) `P` длины `m` — нужно найти, где `P` встречается в `T` (вхождения могут перекрываться).

На практике это основа поиска в редакторах, утилиты `grep`, обработки логов, поиска по геномам и фильтрации текста.

## Наивный поиск

Прикладываем образец `P` к текущей позиции `i` в тексте `T` и сравниваем символы слева направо. Если дошли до конца образца — нашли совпадение. При любом несовпадении (или после нахождения) сдвигаем образец на `1` позицию вправо.

- **Сложность:** в худшем случае `O(n · m)`, на случайных текстах близка к `O(n)`.
- **Плюсы:** максимально простой код, нулевая предобработка.

## Алгоритм Кнута — Морриса — Пратта (KMP)

Когда при сравнении слева направо произошло несовпадение после `j` совпавших символов, мы уже знаем, какие символы стояли в этом месте текста. Если начало образца совпадает с концом уже проверенного куска, можно сдвинуть шаблон сразу на несколько позиций и не перепроверять уже совпавшие символы текста.

Для этого заранее строят массив **префикс-функции** (или `lps`) длины `m` только по самому образцу `P`.

- **Сложность:** `O(n + m)` в худшем случае (и построение таблицы, и поиск линейны).
- **Плюсы:** честная линейная гарантия без деградации на повторяющихся строках; базовая идея переносится на поиск сразу множества шаблонов (алгоритм Ахо — Корасик).

## Алгоритм Бойера — Мура

Алгоритм сравнивает образец `P` с текстом **справа налево** (начиная с конца шаблона). Если символ не совпал, можно сдвинуть шаблон дальше, опираясь на два правила:

1. **Правило плохого символа:** смотрим, где несовпавший символ текста встречается правее в образце `P`, и выравниваем его с этим местом (или сдвигаем весь образец за точку несовпадения, если символа в `P` нет).
2. **Правило хорошего суффикса:** если какой-то суффикс образца уже совпал, ищем в `P` такое же вхождение этого суффикса и выравниваем по нему.

- **Сложность:** на практике часто работает быстрее линейного (сублинейно), потому что многие символы текста вообще пропускаются; в худшем случае с полным правилом хорошего суффикса — `O(n + m)`.
- **Плюсы:** один из самых быстрых алгоритмов для поиска в обычных текстах.

## Алгоритм Рабина — Карпа

Вместо посимвольного сравнения на каждом сдвиге сравниваем **хеш** текущего окна длины `m` в тексте с хешем образца `P`.

Чтобы считать хеш окна за `O(1)` при сдвиге на один символ вправо, используют **скользящий хеш** по модулю простого числа `q`: убирают вклад левого выходящего символа, умножают на основание системы счисления и добавляют новый правый символ.

- **Важно:** если хеши совпали, нужна посимвольная проверка — из-за модуля возможны ложные совпадения.
- **Сложность:** `O(n + m)` в среднем, но в худшем случае при обилии коллизий — `O(n · m)`.
- **Плюсы:** удобно расширяется на поиск сразу нескольких шаблонов одинаковой длины или двумерных шаблонов.

## Реализация на C

Ниже приведены наивный поиск и алгоритм KMP — они хорошо показывают переход от `O(n · m)` к гарантированному `O(n + m)`.

```c
#include <stddef.h>
#include <stdio.h>
#include <string.h>

// Наивный поиск: возвращает индекс первого вхождения P в T или -1
long naiveSearch(const char *text, const char *pattern) {
    size_t n = strlen(text);
    size_t m = strlen(pattern);

    if (m == 0) {
        return 0;
    }
    if (m > n) {
        return -1;
    }

    // Перебираем все возможные стартовые позиции образца в тексте
    for (size_t i = 0; i <= n - m; i++) {
        size_t j = 0;
        // Сравниваем образец с окном текста посимвольно слева направо
        while (j < m && text[i + j] == pattern[j]) {
            j++;
        }
        if (j == m) {
            return (long)i;   // нашли полное совпадение
        }
    }

    return -1;
}

// Строит префикс-функцию (lps) для образца pattern длины m:
// lps[k] — длина наибольшего собственного префикса pattern[0..k],
// который одновременно является суффиксом pattern[0..k]
static void buildLps(const char *pattern, size_t m, size_t *lps) {
    lps[0] = 0;
    size_t len = 0;   // длина предыдущего наибольшего префикса-суффикса
    size_t i = 1;

    while (i < m) {
        if (pattern[i] == pattern[len]) {
            len++;
            lps[i] = len;
            i++;
        } else if (len != 0) {
            // Откатываемся по уже известным совпавшим префиксам
            len = lps[len - 1];
        } else {
            lps[i] = 0;
            i++;
        }
    }
}

// Алгоритм Кнута — Морриса — Пратта: возвращает индекс первого вхождения или -1
long kmpSearch(const char *text, const char *pattern) {
    size_t n = strlen(text);
    size_t m = strlen(pattern);

    if (m == 0) {
        return 0;
    }
    if (m > n) {
        return -1;
    }

    size_t lps[m];
    buildLps(pattern, m, lps);

    size_t i = 0;   // индекс в text (никогда не откатывается назад)
    size_t j = 0;   // индекс в pattern

    while (i < n) {
        if (text[i] == pattern[j]) {
            i++;
            j++;
            if (j == m) {
                return (long)(i - j);   // нашли вхождение
            }
        } else if (j != 0) {
            // Сдвигаем образец по префикс-функции без повторной проверки символов text
            j = lps[j - 1];
        } else {
            i++;
        }
    }

    return -1;
}

int main(void) {
    const char *text = "bbabaxababay";
    const char *pattern = "aba";

    printf("Naive: %ld\n", naiveSearch(text, pattern));  // 3
    printf("KMP:   %ld\n", kmpSearch(text, pattern));    // 3

    return 0;
}
```

## Сравнение алгоритмов

| Алгоритм | Худший случай | Средний случай | Главная идея и область применения |
| :--- | :--- | :--- | :--- |
| **Наивный** | `O(n · m)` | `O(n · m)` | Простой перебор, хорош для обучения и коротких строк |
| **KMP** | `O(n + m)` | `O(n + m)` | Префикс-функция, гарантия линейного времени |
| **Бойер — Мур** | `O(n + m)` | Сублинейный | Сравнение справа налево, быстрый на естественных текстах |
| **Рабин — Карп** | `O(n · m)` | `O(n + m)` | Скользящий хеш, удобен для нескольких образцов |

## Итог

- **Наивный поиск** прост, но в худшем случае работает за `O(n · m)`.
- **KMP** гарантирует линейное время `O(n + m)` за счёт префикс-функции.
- **Бойер — Мур** часто самый быстрый на практике благодаря сравнению справа налево и сдвигам по правилам плохого символа / хорошего суффикса.
- **Рабин — Карп** опирается на скользящий хеш и требует аккуратной проверки при совпадении хешей.
