# Введение в деревья

Вы когда-нибудь задумывались, почему файловая система устроена как папки
внутри папок, а не как один гигантский список файлов? Потому что искать
в списке из миллиона элементов — это перебор. А в дереве — спуск по
нескольким уровням. То же самое с HTML-разметкой, с генеалогическим
древом, с организационной структурой компании, с синтаксисом программы.

Дерево — это структура данных для **иерархии**. Всё, что можно описать
словами «состоит из», «входит в», «является частью» — это дерево.

В этой главе разберёмся: что такое дерево, из чего оно состоит,
как его обходить (это важнее, чем кажется) и почему обходы — это не
академическое упражнение, а рабочий инструмент компилятора.

## Что такое дерево

**Дерево** — это конечное множество узлов, у которого есть один выделенный
узел — **корень**, а все остальные узлы разбиты на непересекающиеся
подмножества, каждое из которых само является деревом. Эти подмножества
называются **поддеревьями** корня.

Звучит заумно. На практике: есть корень, у него есть дети, у детей — свои
дети, и так далее. У каждого узла (кроме корня) ровно один родитель.
Никаких циклов. Никаких «двух родителей».

```
         A          ← корень
        / \
       B   C        ← дети A
      / \   \
     D   E   F      ← листья
```

> **Главная мысль:** дерево — это иерархия без циклов. Файловая система,
> HTML-документ, дерево выражений `a + b * c` — всё это деревья.
> Как только вы видите «вложенность» — скорее всего, перед вами дерево.

## Терминология без скуки

- **Корень** (root) — верхний узел. У него нет родителя.
- **Лист** (leaf) — узел без детей. Конец пути.
- **Родитель** / **потомок** — очевидно.
- **Поддерево** — любой узел вместе со всеми его потомками.
- **Глубина** узла — сколько шагов от корня до него.
- **Высота** дерева — длина самого длинного пути от корня до листа.
  У дерева из одного узла высота 0. У пустого дерева высоты нет вообще.

Высота — самое важное число в этой главе. Запомните: **все операции
с деревом стоят `O(высота)`**. Если дерево «пухлое» и низкое — быстро.
Если дерево вытянулось в одну линию — медленно, как связный список.

## Обходы дерева: зачем их четыре

**Обход** (traversal) — это способ перебрать все узлы дерева в каком-то
порядке. Казалось бы, какая разница, в каком порядке? Огромная.

Представьте дерево выражения `3 * (x + 1)`. Если обойти его одним
способом — получите `3 x 1 + *` (обратная польская запись, её понимает
стековый калькулятор). Другим способом — `* 3 + x 1` (префиксная,
её понимает Lisp). Третьим — `3 * (x + 1)` (инфиксная, привычная нам).
Одно дерево, три разных «языка» — и всё благодаря разному порядку обхода.

Есть четыре классических обхода:

1. **Прямой** (pre-order) — узел, потом дети.
2. **Обратный** (post-order) — дети, потом узел.
3. **Симметричный** (in-order) — левое поддерево, узел, правое поддерево.
4. **В ширину** (BFS) — уровень за уровнем.

Первые три — рекурсивные. Четвёртый — на очереди.

---

## Прямой и обратный порядок

**Прямой обход** (pre-order): сначала посещаем узел, потом — его детей
слева направо.

```text
PREORDER(n):
1  посетить n
2  for каждого ребёнка s узла n слева направо do
3      PREORDER(s)
```

**Обратный обход** (post-order): сначала — дети, потом — узел.

```text
POSTORDER(n):
1  for каждого ребёнка s узла n слева направо do
2      POSTORDER(s)
3  посетить n
```

Разница ровно в одной строке — но результат совершенно разный.

Для дерева `3 * (x + 1)`:

- **Прямой обход** даёт `* 3 + x 1` — это **префиксная** (польская) запись.
- **Обратный обход** даёт `3 x 1 + *` — это **постфиксная** (обратная
  польская) запись. Именно так работают стековые калькуляторы и виртуальные
  машины вроде JVM.

> **Важно:** прямой обход удобен, когда вы **копируете** дерево или
> **сериализуете** его в файл — родитель должен быть записан раньше детей.
> Обратный обход — когда вы **удаляете** дерево или **вычисляете**
> выражение — дети должны быть обработаны раньше родителя.

## Симметричный обход

**Симметричный** (или центрированный) обход: сначала левое поддерево,
потом сам узел, потом правое поддерево.

```text
INORDER(n):
1  INORDER(левый ребёнок n)
2  посетить n
3  INORDER(правый ребёнок n)
```

Для бинарного дерева это выглядит так: спустились до самого левого листа,
посетили его, вернулись к родителю, посетили родителя, ушли в правое
поддерево. И так далее.

Зачем это нужно? Вот главное свойство: **если дерево — это бинарное дерево
поиска (BST), симметричный обход даёт отсортированный по возрастанию
список ключей**. Именно поэтому BST так популярны для упорядоченных
множеств. Подробнее — в следующей главе.

> **Главная мысль:** симметричный обход — это «прочитать дерево слева
> направо». Для BST это даёт сортировку бесплатно. Для дерева выражения —
> инфиксную запись (но со скобками, которые нужно восстанавливать
> по структуре).

## Обход в ширину

**Обход в ширину** (breadth-first, BFS) — единственный из четырёх,
который **не рекурсивный**. Он идёт **уровень за уровнем**, слева направо.

```
         A          ← уровень 0
        / \
       B   C        ← уровень 1
      / \   \
     D   E   F      ← уровень 2
```

BFS обойдёт это как `A B C D E F`.

Реализуется через **очередь**:

1. Кладём корень в очередь.
2. Пока очередь не пуста:
   - достаём узел из головы;
   - обрабатываем его;
   - кладём всех его детей в хвост очереди.

```c
void bfs(Node *root) {
    if (root == NULL) return;
    Queue q;
    queueInit(&q);
    queuePush(&q, root);
    while (!queueIsEmpty(&q)) {
        Node *n = queuePop(&q);
        printf("%d ", n->key);
        if (n->left)  queuePush(&q, n->left);
        if (n->right) queuePush(&q, n->right);
    }
}
```

> **Важно:** BFS не работает рекурсией «в лоб» — рекурсия по своей природе
> это DFS (стек), а не BFS (очередь). Попытка сделать BFS рекурсивно
> превращается в обход по уровням с дополнительным массивом. Проще
> использовать очередь.

Где это нужно: поиск кратчайшего пути в невзвешенном графе, обход
файловой системы «по уровням вложенности», сериализация дерева
«по слоям».

## Применение в компиляторах

Деревья выражений — это сердце любого компилятора и интерпретатора.
Парсер строит дерево из текста программы, а потом обходы дают разные
представления.

| Обход | Что даёт | Где используется |
|-------|----------|------------------|
| Прямой | Префиксная запись | Lisp, Clojure, сериализация |
| Обратный | Постфиксная запись | Стековые машины, JVM, вычисление выражений |
| Симметричный | Инфиксная запись | Печать выражений для человека |
| В ширину | Уровни | Печать дерева «по слоям», сериализация |

Оптимизации компилятора тоже работают через обходы:

- **Свёртка констант** — если оба ребёнка узла-операции оказались
  константами, заменить узел результатом. Это пост-обход: сначала
  обработать детей.
- **Устранение общих подвыражений** — найти одинаковые поддеревья
  и заменить их ссылкой на одно. Это тоже обход с анализом.
- **Распространение констант** — пройти по дереву, подставляя известные
  значения. Обычно прямой обход.

> **Главная мысль:** обходы — это не «упражнение для экзамена».
> Это рабочий инструмент. Каждый раз, когда вы пишете рекурсивную
> функцию по дереву, вы выбираете один из обходов — часто не осознавая
> этого.

## Итог

- **Дерево** — иерархическая структура без циклов, с выделенным корнем.
- **Высота** дерева определяет стоимость всех операций: `O(h)`.
- Четыре классических обхода: **прямой**, **обратный**, **симметричный**, **в ширину**.
- **Прямой** обход → префиксная запись, сериализация, копирование.
- **Обратный** обход → постфиксная запись, вычисление, удаление.
- **Симметричный** обход BST → отсортированный массив.
- **BFS** идёт по уровням и использует очередь, а не рекурсию.
- Деревья выражений — основа компиляторов; каждый обход даёт своё представление.
