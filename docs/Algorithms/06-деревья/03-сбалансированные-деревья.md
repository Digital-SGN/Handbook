# Сбалансированные деревья

В предыдущей главе мы построили BST и сказали: «Все операции — `O(h)`».
А потом добавили: «Если дерево сбалансировано». Вот это «если» — самое
больное место BST.

Вставьте ключи `1, 2, 3, 4, 5, 6, 7` по порядку — и получите не дерево,
а **палку**: каждый новый узел становится правым ребёнком предыдущего.
Высота — `n`, поиск — `O(n)`, BST превратилось в связный список. Вся
прелесть `O(log n)` испарилась.

Сбалансированные деревья решают эту проблему: они **сами себя
перестраивают** при вставке и удалении, чтобы высота всегда оставалась
`O(log n)`.

## Идея балансировки

**Идеально сбалансированное** дерево — это такое, где для каждой вершины
число вершин в левом и правом поддеревьях отличается не более чем на 1.
Такое дерево имеет высоту `⌈log₂ n⌉` — теоретический минимум.

Проблема: **поддерживать идеальный баланс после каждой вставки — очень
дорого**. Одна вставка может потребовать перестройки всего дерева.

Поэтому на практике используют **менее строгие критерии**:

- AVL-деревья: высоты поддеревьев отличаются не более чем на 1.
- Красно-чёрные деревья: «чёрная высота» одинакова у всех путей.
- B-деревья: все листья на одной глубине, много ключей в узле.

Все они дают высоту `O(log n)` и поддерживают её за `O(log n)` операций
на вставку/удаление.

> **Главная мысль:** балансировка — это компромисс. Идеальный баланс
> слишком дорог, а логарифмическая высота достигается и при более слабых
> критериях.

## АВЛ-деревья

Названы в честь **Адельсона-Вельского** и **Ландиса** — двух советских
математиков, предложивших эту идею в 1962 году. Требуют всего **два бита**
на узел (для хранения баланса) и гарантируют высоту `O(log n)`.

**Определение.** BST называется **АВЛ-сбалансированным**, если для
каждого узла высота левого поддерева отличается от высоты правого
**не более чем на 1**.

```
       OK               НЕ OK
        5                 5
       / \               /
      3   7             3
     /                 /
    2                 2
                     /
                    1
```

Адельсон-Вельский и Ландис доказали: высота АВЛ-дерева с `n` узлами
не превышает `1.4405 · log₂(n+2) − 0.3277`. То есть путь поиска не более
чем на **45%** длиннее идеально сбалансированного.

### Вставка в АВЛ

1. Вставляем ключ как в обычный BST (спуск до листа).
2. Поднимаемся обратно к корню, обновляя показатели баланса.
3. Если в каком-то узле баланс нарушился — делаем **поворот**.

Поворот — это локальная перестройка 2–3 узлов, которая восстанавливает
баланс, не ломая свойство BST. Всего четыре вида поворотов, но каждый —
это 5–6 строк кода.

## Повороты АВЛ

Повороты — самая «страшная» часть АВЛ, но на самом деле это просто
перевешивание указателей. Разберём малый левый поворот.

**Было:**

```
        p
       / \
      A   q
         / \
        B   C
```

**Стало** (левый поворот вокруг `p`):

```
        q
       / \
      p   C
     / \
    A   B
```

Код — **пять строк**:

```c
Node *rotateLeft(Node *p) {
    Node *q = p->right;
    p->right = q->left;
    q->left = p;
    return q;   // новый корень поддерева
}
```

Малый правый поворот — симметрично:

```c
Node *rotateRight(Node *p) {
    Node *q = p->left;
    p->left = q->right;
    q->right = p;
    return q;
}
```

**Большой поворот** — это два малых подряд. Например, если баланс
нарушился в «зигзаг» (левый-правый), сначала делаем правый поворот
у ребёнка, потом левый у родителя.

> **Важно:** повороты не меняют порядок ключей. Свойство BST сохраняется.
> Меняется только форма дерева — и именно она восстанавливает баланс.

На практике вам почти никогда не придётся писать АВЛ-дерево руками.
Но понимать повороты полезно: они же используются в красно-чёрных
деревьях, в splay-деревьях, в treap.

## Красно-чёрные деревья

Идея Баера (1972) — **менее строгий** баланс, но **более быстрые**
вставка и удаление. Вместо хранения высот у каждого узла держат цвет:
**красный** или **чёрный**.

**Свойства:**

1. Корень — **чёрный**.
2. Каждый узел либо красный, либо чёрный.
3. Листья (`NIL`) считаются чёрными.
4. У красного узла **оба ребёнка чёрные** (нет двух красных подряд).
5. Все пути от корня к листьям содержат **одинаковое число чёрных** узлов.

Из свойств 4 и 5 следует: **самый длинный путь не более чем вдвое
длиннее самого короткого**. Значит, высота `O(log n)`.

Вставка и удаление могут нарушить свойства. Восстанавливают их
**перекрашиванием** узлов и **поворотами** — теми же, что в АВЛ.

> **Главная мысль:** красно-чёрное дерево — это «АВЛ наоборот».
> Баланс слабее, высота чуть больше, но вставка и удаление требуют
> меньше перестроек. Поэтому именно красно-чёрные деревья используют
> в стандартных библиотеках.

## Сравнение

| Свойство | АВЛ-дерево | Красно-чёрное дерево |
|----------|------------|----------------------|
| Строгость баланса | Сильнее | Слабее |
| Высота | `≈ 1.44 · log n` | `≈ 2 · log n` |
| Поиск | Быстрее | Чуть медленнее |
| Вставка / удаление | Медленнее | Быстрее |
| Где используется | Редко в стандартных библиотеках | `std::map`, `TreeMap`, ядро Linux |

**Что выбрать:**

- Если **читаете чаще, чем пишете** — АВЛ.
- Если **пишете часто** — красно-чёрное.
- Если пишете **свой** код — **не пишите ни то, ни другое**.
  Используйте `std::map` / `TreeMap` / `BTreeMap`. Они уже отлажены
  и оптимизированы.

## Итог

- **Вырожденное BST** — это связный список. Все операции `O(n)`.
- **Идеальный баланс** слишком дорог. На практике — ослабленные критерии.
- **АВЛ-дерево** — высоты поддеревьев отличаются не более чем на 1.
  Высота `≈ 1.44 · log n`, поиск быстрый, вставка медленнее.
- **Повороты** — локальная перестройка 2–3 узлов. Пять строк кода.
  Свойство BST при поворотах сохраняется.
- **Красно-чёрное дерево** — слабее баланс, но быстрее вставка/удаление.
  Высота `≈ 2 · log n`.
- В стандартных библиотеках — **красно-чёрные деревья** (`std::map`,
  `TreeMap`). Своё АВЛ пишут только в учебных целях или в специфичных
  задачах (например, в embedded, где важна каждая аллокация).
