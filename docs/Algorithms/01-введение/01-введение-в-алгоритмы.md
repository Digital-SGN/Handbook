# Введение в алгоритмы

**Алгоритм** — это чёткая последовательность шагов, которая превращает входные данные в нужный результат за конечное время.

В реальной разработке алгоритмы редко пишут с нуля — чаще используют готовые функции из стандартной библиотеки. Но без понимания того, как они работают внутри, легко получить код, который отлично бегает на 100 записях и «вешает» сервер на 100 000.

## Зачем нужны алгоритмы и откуда взялось слово

Даже если вы делаете обычный CRUD-сервис или интерфейс, алгоритмы работают под капотом: в поиске по базе, сортировке списков, маршрутизации запросов, сжатии данных и компиляторах[cite: 1]. Хороший инженер отличается от новичка тем, что видит узкие места до того, как они станут проблемой в продакшене[cite: 1].

Слово *«алгоритм»* пришло из средневековой латыни как искажённое имя персидского математика **аль-Хорезми** (IX век)[cite: 1]. В Европе так называли правила вычислений в десятичной системе счисления — в противовес счёту на счётных досках (абаке)[cite: 1]. А от названия его трактата об уравнениях (*«Аль-джабр»*) произошло слово *«алгебра»*[cite: 1].

## Когда инструкция — это ещё не алгоритм

Не любой набор шагов можно назвать алгоритмом. У алгоритма есть пять обязательных свойств:

1. **Ввод** — на вход подаётся ноль или больше значений (например, массив чисел или строка).
2. **Вывод** — на выходе получаем хотя бы один осмысленный результат, связанный со входом.
3. **Определённость** — каждый шаг описан однозначно, без «сделай как-нибудь» и «на глаз».
4. **Конечность** — алгоритм обязан остановиться через конечное число шагов. Если процесс крутится вечно (например, бесконечный цикл или несходящаяся процедура), это не алгоритм, а «метод вычислений».
5. **Эффективность** — каждый шаг должен быть выполнимым и элементарным (сложить, сравнить, присвоить), а не требовать «угадать ответ» или «измерить отрезок с бесконечной точностью»[cite: 1].

## Псевдокод и доказательство правильности

Писать логику сразу на целевом языке не всегда удобно: синтаксис, типы, обработка ошибок и boilerplate-код отвлекают от самой идеи[cite: 1]. Для разбора идей используют **псевдокод** — смесь обычного языка и базовых конструкций программирования[cite: 1].

Возьмём простую задачу: найти максимум в непустом массиве `A` длины `n`[cite: 1].

```text
алгоритм arrayMax(A, n):
    currentMax ← A[0]
    для i от 1 до n - 1:
        если A[i] > currentMax:
            currentMax ← A[i]
    вернуть currentMax
```

И тот же алгоритм на Java (осторожно с пустыми массивами — в реальном коде стоит добавить проверку `n == 0`)[cite: 1]:

```java
public class ArrayMax {
    static int arrayMax(int[] a) {
        if (a == null || a.length == 0) {
            throw new IllegalArgumentException("Массив не должен быть пустым");
        }
        int currentMax = a[0];
        for (int i = 1; i < a.length; i++) {
            if (a[i] > currentMax) {
                currentMax = a[i];
            }
        }
        return currentMax;
    }

    public static void main(String[] args) {
        int[] numbers = {10, 15, 3, 5, 56, 107, 22, 16, 85};
        System.out.println("Максимум: " + arrayMax(numbers));
    }
}
```

### Как убедиться, что алгоритм вообще работает?

Помогает **инвариант цикла** — утверждение, которое истинно до цикла, сохраняется на каждом шаге и даёт нужный результат после завершения[cite: 1]:

- **До цикла (`i = 1`):** `currentMax` равен `A[0]` — это максимум среди первого элемента.
- **На шаге `i`:** если `currentMax` был максимумом среди элементов `A[0..i-1]`, то после сравнения с `A[i]` он станет максимумом среди `A[0..i]`.
- **После цикла (`i = n`):** `currentMax` — максимум среди всех `n` элементов[cite: 1].

## Как оценивать скорость без секундомера

Замерять время на ноутбуке через таймер полезно для профиля конкретного сервиса, но плохо для сравнения алгоритмов[cite: 1]:

- результат зависит от процессора, ОС, фоновых процессов и языка;
- нельзя прогнать код на всех возможных входных данных;
- приходится сначала написать полную реализацию[cite: 1].

Вместо секунд считают **элементарные операции** (присваивание, сравнение, арифметику, обращение по индексу) в зависимости от размера входа `n`[cite: 1]. Каждая такая операция занимает какое-то константное время на конкретном железе[cite: 1].

В `arrayMax` на каждом шаге цикла выполняется сравнение и, возможно, обновление `currentMax`[cite: 1]. Итоговое число операций зависит от `n` линейно (от `5n` до `7n - 2` в зависимости от данных)[cite: 1]. Но вдаваться в точные коэффициенты вроде `7n - 2` на практике почти никогда не нужно — об этом подробнее в следующей главе[cite: 1, 2].

## Лучший, средний и худший случаи

Один и тот же алгоритм на разных данных может вести себя по-разному[cite: 1]:

- **Лучший случай** — данные максимально «удобны» для алгоритма (например, нужный элемент стоит первым). На него опасно ориентироваться: в жизни так везёт редко.
- **Средний случай** — ожидаемое время на «типичных» данных. Хорошая метрика, но её сложно посчитать честно без знания реального распределения входных данных и теории вероятностей.
- **Худший случай** — максимальное число шагов на входе размера `n`[cite: 1].

По умолчанию в анализе алгоритмов чаще всего смотрят на **худший случай**[cite: 1]. Это честная гарантия: «медленнее этого алгоритм на входе размера `n` точно не сработает»[cite: 1].

## Шпаргалка

- Алгоритм обязан быть **конечным**, **определённым** и **эффективным**, иметь **ввод** и **вывод**.
- **Псевдокод** нужен, чтобы обсуждать логику алгоритма без шума синтаксиса.
- Вместо замеров в секундах оценивают рост числа операций от размера входа `n`.
- По умолчанию ориентируются на **худший случай** — это надёжная верхняя планка[cite: 1].
