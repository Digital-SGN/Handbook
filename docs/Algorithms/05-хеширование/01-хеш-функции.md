# Хеш-функции: как превратить строку в число

Представьте библиотеку на миллион книг, где книги расставлены не по алфавиту,
а по последней цифре ISBN. Найти нужную — секунды. А теперь представьте, что
все ISBN заканчиваются на 7. Библиотека превращается в свалку, и вы снова
перебираете миллион корешков.

Хеш-функция — это и есть правило «куда поставить книгу». Хорошее правило
даёт вам мгновенный доступ. Плохое — превращает структуру данных в связный
список, только медленнее.

В этой главе разберёмся: что такое хеш-функция, какой она должна быть,
как её писать руками и почему `hash("hello")` в Python и в Java дадут
разные числа.

---

## Что такое хеш-функция

**Хеш-функция** — это функция, которая берёт данные произвольной длины
(строку, число, объект) и возвращает число фиксированного диапазона.

```
hash: ключ → целое число в [0, m)
```

где `m` — размер нашей таблицы (массива, куда мы будем складывать элементы).

Два свойства, которые важны всегда:

1. **Детерминизм.** Один и тот же ключ → одно и то же число. Всегда.
   Иначе `put("alice", 30)` и `get("alice")` попадут в разные ячейки,
   и словарь просто не будет работать.
2. **Равномерность.** Разные ключи → по возможности разные числа.
   Если все ключи сваливаются в одну ячейку, мы получаем список,
   а не таблицу.

> **Главная мысль:** хеш-функция — это не шифрование и не магия.
> Это просто «перемешать и взять остаток». Всё остальное — детали,
> которые влияют на скорость.

---

## Откуда берётся число: остаток по модулю

Самый простой вариант для целых ключей:

```c
size_t hash_int(int key, size_t m) {
    return (size_t)key % m;
}
```

Для `m = 16` ключи `0, 16, 32, 48` попадут в одну ячейку. Это называется
**коллизией** — о ней вся следующая глава. Пока просто запомните: коллизии
неизбежны, потому что ключей бесконечно много, а ячеек — `m`.

Модуль по степени двойки (`m = 2^k`) работает быстро (это просто побитовое
«И» с маской), но плохо, если ключи имеют структуру — например, все кратны 16.
Поэтому в реальных реализациях `m` берут простым числом или используют
специальные приёмы (об этом ниже).

---

## Хеширование строк: полиномиальный хеш

Строку в число превращают через **полиномиальный хеш**:

```
h = (s[0] * p^(n-1) + s[1] * p^(n-2) + ... + s[n-1]) mod m
```

Где `p` — небольшое простое число (обычно 31, 33, 37 или 131),
а `m` — размер таблицы. Идея: каждый символ «взвешивается» своей позицией,
поэтому `"ab"` и `"ba"` дают разные хеши.

Считать это в лоб через степени — долго. Используют схему Горнера:

```
h = 0
for c in s:
    h = (h * p + c) mod m
```

Это `O(n)` по длине строки и без возведения в степень.

```c
size_t hash_string(const char *s, size_t m) {
    size_t h = 0;
    const size_t p = 31;
    for (; *s; s++) {
        h = (h * p + (unsigned char)*s) % m;
    }
    return h;
}
```

> **Важно:** `(unsigned char)*s`, а не `*s`. `char` в C может быть знаковым,
> и для байтов ≥ 128 вы получите отрицательное число, которое при
> приведении к `size_t` станет огромным. Классическая ошибка.

Почему `p = 31`? Историческая привычка из Java (`String.hashCode`).
Работает нормально для латиницы. Для кириллицы, эмодзи и вообще UTF-8
лучше брать `p = 131` или `p = 1_000_003`, а ещё лучше — не писать свою
хеш-функцию для строк вообще (см. ниже).

---

## Хеш-функция должна быть быстрой

Соблазн: «Давайте сделаем супер-стойкий хеш, как SHA-256!» Плохая идея
для хеш-таблицы.

- SHA-256 — это **криптографическая** хеш-функция. Её задача — чтобы по хешу
  нельзя было восстановить вход и чтобы нельзя было подобрать коллизию.
  Это дорого: десятки операций на байт.
- Хеш-таблица хочет **просто разбросать** ключи по ячейкам. Ей не важна
  стойкость, важна скорость и равномерность.

Криптографический хеш в хеш-таблице — это как бронированная дверь
в сарае. Дорого, медленно, а от чего защищает — непонятно.

> **Главная мысль:** для хеш-таблиц используют **некриптографические**
> хеш-функции: FNV-1a, MurmurHash, xxHash, CityHash. Они в разы быстрее
> и достаточно равномерны.

---

## FNV-1a: хеш, который реально используется

Простая и очень распространённая функция. Идея: начать с «магической»
константы, потом для каждого байта — XOR, потом умножить на другое
«магическое» число.

```c
#define FNV_OFFSET 1469598103934665603ULL
#define FNV_PRIME  1099511628211ULL

size_t hash_fnv1a(const char *s, size_t m) {
    size_t h = FNV_OFFSET;
    for (; *s; s++) {
        h ^= (unsigned char)*s;
        h *= FNV_PRIME;
    }
    return h % m;
}
```

Почему это работает: умножение на нечётное простое «размазывает» биты,
XOR вносит каждый байт, а константы подобраны так, чтобы даже короткие
строки давали хорошо различимые числа. Для 64-битных `size_t` работают
64-битные константы (как выше). Для 32-битных — свои (меньше).

FNV-1a — отличный дефолт, если вам нужна своя хеш-функция и вы не хотите
думать. Она быстрая, короткая и достаточно равномерная.

## Универсальное хеширование (коротко)

Есть теоретическая проблема: **для любой фиксированной хеш-функции
существует набор ключей, который её ломает.** Злоумышленник может
подобрать такие строки, что все они попадут в одну ячейку, и словарь
превратится в список — это называется **hash-flooding атакой**.

Защита: выбирать хеш-функцию **случайно** из семейства при старте программы
(рандомизированное хеширование). Именно так работает Python: `hash(str)`
разный при каждом запуске интерпретатора (если не выставлен
`PYTHONHASHSEED`).

Вам в реальном коде это почти никогда не нужно реализовывать руками —
это забота стандартной библиотеки. Но знать, почему `hash("abc")` в Python
меняется от запуска к запуску, полезно.

---

## Как это выглядит в разных языках

| Язык       | Что делает `hash` для строк                           |
|------------|-------------------------------------------------------|
| C          | Нет встроенного. Пишете сами (FNV, MurmurHash)        |
| C++        | `std::hash<std::string>` — зависит от реализации      |
| Java       | `String.hashCode`: `h = 31*h + c`                     |
| Python     | SipHash с случайным seed (защита от hash-flooding)    |
| Go         | Рантайм-хеш с рандомизацией                            |
| Rust       | `std::hash::Hash` — по умолчанию SipHash-1-3          |

Общее правило: **не пишите свою хеш-функцию для строк, если в языке
есть стандартная.** Стандартная уже прошла через атаки, бенчмарки
и багфиксы.

---

## Итог

- Хеш-функция превращает ключ в число в диапазоне `[0, m)`, где `m` — размер таблицы.
- Два обязательных свойства: **детерминизм** и **равномерность**.
- Для целых — остаток по модулю, но `m` лучше брать простым.
- Для строк — полиномиальный хеш (схема Горнера) или FNV-1a.
- Криптографические хеши (SHA, MD5) для хеш-таблиц **не нужны** — они медленные.
- Свою хеш-функцию для строк пишите, только если её нет в стандартной библиотеке.
- Случайный seed защищает от hash-flooding — так делают Python, Go, Rust.
