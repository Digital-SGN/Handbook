# Кратчайшие пути

Представьте навигатор. У вас есть карта города — вершины это перекрёстки,
рёбра — дороги, веса — время в пути. Вопрос: «как доехать из точки A
в точку B быстрее всего?» Это самая практическая задача на графах,
и решается она **алгоритмом Дейкстры**.

Но не всё так просто. Дороги бывают **односторонние** (ориентированный
граф), **пробки** меняют веса (граф динамический), а иногда веса
**отрицательные** — например, если вы моделируете не расстояния, а
**прибыль** или **энергию** (спуск с горы отнимает энергию, подъём
добавляет — вес ребра может быть отрицательным). И вот тут Дейкстра
ломается.

В этой главе разберёмся:

- как работает **Дейкстра** — рабочая лошадка 90% задач;
- почему он **ломается** на отрицательных весах;
- что делать, когда веса отрицательные — **Беллман-Форд**;
- как найти **все пары** кратчайших путей сразу — **Флойд-Уоршелл**.

## Постановка задачи

Есть **взвешенный граф** `G = (V, E)`, где у каждого ребра `(u, v)`
есть вес `w(u, v)` — обычно неотрицательное число. Есть **стартовая
вершина** `s`.

Нужно найти **кратчайшие расстояния** от `s` до **всех** остальных
вершин — то есть минимальную сумму весов по всем путям.

```
        A --4--> B
        |        |
        1        2
        ↓        ↓
        C --3--> D

Кратчайшие от A:
  A: 0
  B: 4   (A → B)
  C: 1   (A → C)
  D: 4   (A → C → D = 1 + 3 = 4, лучше чем A → B → D = 4 + 2 = 6)
```

**Варианты задачи:**

- **Из одной вершины во все** (single-source) — Дейкстра, Беллман-Форд.
- **Из одной во все с отрицательными весами** — Беллман-Форд.
- **Между двумя конкретными** — тоже Дейкстра, просто останавливаемся
  раньше.
- **Между всеми парами** (all-pairs) — Флойд-Уоршелл, или `n` раз
  Дейкстра.

> **Главная мысль:** «кратчайший путь» — это **минимум суммы весов**,
> а не минимум рёбер. В невзвешенном графе это одно и то же (все веса
> равны 1), и тогда работает BFS. Взвешенный граф — нужны Дейкстра
> или Беллман-Форд.

---

## Дейкстра: идея

**Алгоритм Дейкстры** (Edsger Dijkstra, 1956) — жадный алгоритм.
Идея: **жадно берём ближайшую необработанную вершину** и «релаксируем»
её соседей.

Пошагово:

1. `dist[s] = 0`, `dist[всех остальных] = ∞`.
2. `visited` — пустое множество.
3. Пока есть необработанные вершины:
   - выбираем вершину `u` с **минимальным** `dist[u]` среди
     необработанных;
   - помечаем `u` обработанной;
   - для каждого соседа `v`: если `dist[u] + w(u,v) < dist[v]` —
     обновляем `dist[v]`.

**Почему это работает?** Когда мы выбираем вершину `u` с минимальным
`dist[u]`, мы **гарантируем**, что короче до неё добраться нельзя.
Потому что любой другой путь до `u` шёл бы через какую-то
необработанную вершину `x` с `dist[x] ≥ dist[u]`, а значит, был бы
не короче. Это **свойство неотрицательных весов** — и именно здесь
Дейкстра ломается, если веса отрицательные (см. ниже).

**Сложность «наивной» версии:**

- `n` раз ищем минимум среди `n` вершин — `O(n²)`.
- Каждое ребро релаксируем один раз — `O(m)`.
- Итого `O(n² + m) = O(n²)`.

Для плотных графов (`m ≈ n²`) это **оптимально**. Для разреженных —
можно лучше, если использовать **приоритетную очередь** (см. ниже).

## Дейкстра с бинарной кучей

Наивная версия ищет минимум **линейным перебором** — `O(n)` на каждом
шаге. Но если хранить `dist` в **приоритетной очереди** (обычно
бинарная куча), минимум достаётся за `O(log n)`.

**Идея:**

1. Кладём в кучу `(dist, vertex)` для всех вершин. Изначально
   `(0, s)` и `(∞, остальные)`.
2. Пока куча не пуста:
   - достаём `(d, u)` с минимальным `d`;
   - если `d > dist[u]` — это устаревшая запись, пропускаем
     (**lazy deletion**);
   - иначе релаксируем соседей: если `dist[u] + w < dist[v]` —
     обновляем `dist[v]` и **кладём в кучу новую пару** `(dist[v], v)`.

**Почему не «уменьшение ключа»?** В классической бинарной куче
операция `decrease-key` требует знать позицию элемента в куче. Это
неудобно. Вместо этого кладут **новую** пару `(новый_dist, v)`, а
старую потом просто игнорируют (lazy deletion). Куча может содержать
до `m` элементов — это нормально.

**Сложность:**

- Каждое ребро может добавить одну запись в кучу → `O(m)` записей.
- Каждое извлечение — `O(log m) = O(log n)`.
- Итого `O((n + m) log n)`.

Для разреженного графа (`m ≈ n`) это `O(n log n)` — гораздо лучше
`O(n²)`.

> **Главная мысль:** «Дейкстра» — это не один алгоритм, а **семейство**.
> Наивная версия `O(n²)`, с кучей `O((n+m) log n)`, с фибоначчиевой
> кучей `O(m + n log n)`. Выбор зависит от плотности графа. На
> практике чаще всего берут **бинарную кучу** — она простая и быстрая.

## Почему Дейкстра ломается на отрицательных весах

Вот пример, на котором Дейкстра даёт **неправильный** ответ:

```
        A --1--> B
        |        
        2        
        ↓        
        C --(-5)--> B
```

Дейкстра из A:

1. `dist = [A=0, B=∞, C=∞]`. Обрабатываем A.
2. `dist[B] = 1`, `dist[C] = 2`.
3. **Берём B** (min dist = 1). Помечаем B обработанной. У B нет
   исходящих рёбер.
4. Берём C (min dist = 2). Релаксируем: `dist[B] = min(1, 2 + (-5)) = -3`.
   Но B **уже обработана** Дейкстра её больше не тронет.
5. Ответ: `dist[B] = 1`.

**Правильный ответ:** `dist[B] = -3` (путь `A → C → B`).

Вот он, момент поломки. Дейкстра **зафиксировал** `dist[B] = 1`,
потому что на тот момент `B` была ближайшей необработанной. Но потом
нашёлся более короткий путь через отрицательное ребро. Дейкстра
этого не предусматривает.

> **Важно:** Дейкстра **не работает** с отрицательными весами, потому
> что он **фиксирует** расстояния. Как только вершина помечена
> обработанной, её `dist` больше не меняется — а при отрицательных
> весах это неверно.

**Что делать?** Два варианта:

1. Если отрицательных весов **нет** — Дейкстра, и всё хорошо.
2. Если **есть** — **Беллман-Форд**.

## Беллман-Форд

**Алгоритм Беллмана-Форда** (1958) работает с **любыми** весами —
в том числе отрицательными. Идея: **релаксируем все рёбра `n−1` раз**.

Почему `n−1`? Потому что кратчайший путь в графе без отрицательных
циклов содержит **не более `n−1` рёбер**. Одна итерация «прохода
по всем рёбрам» гарантированно находит все кратчайшие пути длины
`≤ k`. Значит, `n−1` итераций находят пути длины `≤ n−1` — а это
все возможные.

1. `dist[s] = 0`, `dist[остальных] = ∞`.
2. Повторить `n−1` раз:
   - для каждого ребра `(u, v, w)`:
     - если `dist[u] + w < dist[v]` — обновить `dist[v]`.
3. **Проверка на отрицательный цикл:** пройти по всем рёбрам ещё раз.
   Если хоть одно ребро можно релаксировать — значит, есть
   **отрицательный цикл**. В этом случае кратчайшего пути не
   существует (можно бесконечно уменьшать расстояние).

**Сложность:** `O(n · m)`. Для плотного графа — `O(n³)`. Для
разреженного — `O(n²)`. Медленнее Дейкстры, но зато работает с
отрицательными весами.

**Отрицательный цикл** — это цикл, сумма весов которого отрицательна.
Например, `A → B → C → A` с весами `1, 1, -3`. Проходя по циклу,
мы каждый раз уменьшаем расстояние на 1 — и так до минус бесконечности.
В таком графе «кратчайшего пути» не существует, и Беллман-Форд это
**обнаруживает**.

> **Главная мысль:** Беллман-Форд — это «Дейкстра для отрицательных
> весов». Медленнее, но универсальнее. И он единственный из
> классических алгоритмов, который **детектит отрицательные циклы**.

---

## Флойд-Уоршелл

**Алгоритм Флойда-Уоршелла** (1962) решает **другую** задачу: найти
кратчайшие пути между **всеми парами** вершин сразу.

Идея — **динамическое программирование**. Пусть `d[i][j]` — кратчайшее
расстояние от `i` до `j`, использующее только вершины из множества
`{0, 1, ..., k}` как промежуточные. Тогда:

```
d[i][j] = min(d[i][j], d[i][k] + d[k][j])
```

То есть: либо путь `i → j` не проходит через `k`, либо проходит —
и тогда он состоит из `i → k` и `k → j`.

Три вложенных цикла:

```c
for (int k = 0; k < n; k++)
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            if (d[i][k] + d[k][j] < d[i][j])
                d[i][j] = d[i][k] + d[k][j];
```

**Сложность:** `O(n³)`. Память: `O(n²)`.

**Почему `k` — внешний цикл?** Это критично. Если поменять местами
`k` и `i`, алгоритм будет неправильным. Смысл в том, что после
итерации `k` мы знаем все кратчайшие пути, использующие вершины
`0..k` как промежуточные. На следующей итерации добавляем `k+1`.

**Отрицательные циклы:** Флойд тоже их детектит — если после
алгоритма `d[i][i] < 0` для какой-то `i`, значит, есть отрицательный
цикл через `i`.

> **Главная мысль:** Флойд — это ДП на матрице смежности. `O(n³)`,
> но зато **сразу все пары**. Для маленьких графов (`n ≤ 400`) —
> идеально. Для больших — `n` раз Дейкстра лучше.

## Сравнение

| Алгоритм | Задача | Отрицательные веса | Сложность | Когда использовать |
|----------|--------|-------------------|-----------|-------------------|
| **BFS** | Из одной во все, невзвешенный | — | `O(V + E)` | Веса не важны |
| **Дейкстра (наивная)** | Из одной во все | ❌ | `O(n²)` | Плотный граф |
| **Дейкстра (куча)** | Из одной во все | ❌ | `O((n+m) log n)` | Разреженный граф |
| **Беллман-Форд** | Из одной во все | ✅ | `O(n·m)` | Отрицательные веса, детект цикла |
| **Флойд-Уоршелл** | Все пары | ✅ | `O(n³)` | Маленький граф, все пары |

**Правило выбора:**

- Весов нет или все равны → **BFS**.
- Веса неотрицательные, граф разреженный → **Дейкстра с кучей**.
- Веса неотрицательные, граф плотный → **Дейкстра наивная**.
- Веса могут быть отрицательными → **Беллман-Форд**.
- Нужны все пары, `n` маленькое → **Флойд**.
- Нужны все пары, `n` большое, веса неотрицательные → `n` раз
  **Дейкстра**.

> **Важно:** «Дейкстра» в реальных задачах — это 90% случаев. Если
> в условии не сказано «отрицательные веса», почти наверняка
> подразумевается Дейкстра. Но **проверяйте** — это классическая
> ловушка на собеседованиях.

## Реализация на C

Реализуем Дейкстру с бинарной кучей — это самая практичная версия.
Кучу напишем вручную, чтобы показать, как она работает.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>
#include <limits.h>

/* ... структуры Graph и AdjNode из первой главы ... */

/* ---------- Бинарная min-куча ---------- */
/* Храним пары (dist, vertex). Сравниваем по dist. */
typedef struct {
    int dist;
    int vertex;
} HeapItem;

typedef struct {
    HeapItem *data;
    int size;
    int cap;
} MinHeap;

MinHeap* heapCreate(int cap) {
    MinHeap *h = malloc(sizeof(MinHeap));
    h->data = malloc(cap * sizeof(HeapItem));
    h->size = 0;
    h->cap = cap;
    return h;
}

static void heapSwap(HeapItem *a, HeapItem *b) {
    HeapItem t = *a; *a = *b; *b = t;
}

static void heapSiftUp(MinHeap *h, int i) {
    while (i > 0) {
        int parent = (i - 1) / 2;
        if (h->data[parent].dist <= h->data[i].dist) break;
        heapSwap(&h->data[parent], &h->data[i]);
        i = parent;
    }
}

static void heapSiftDown(MinHeap *h, int i) {
    while (true) {
        int l = 2 * i + 1, r = 2 * i + 2, smallest = i;
        if (l < h->size && h->data[l].dist < h->data[smallest].dist) smallest = l;
        if (r < h->size && h->data[r].dist < h->data[smallest].dist) smallest = r;
        if (smallest == i) break;
        heapSwap(&h->data[i], &h->data[smallest]);
        i = smallest;
    }
}

void heapPush(MinHeap *h, int dist, int vertex) {
    if (h->size == h->cap) {
        h->cap *= 2;
        h->data = realloc(h->data, h->cap * sizeof(HeapItem));
    }
    h->data[h->size] = (HeapItem){dist, vertex};
    heapSiftUp(h, h->size);
    h->size++;
}

HeapItem heapPop(MinHeap *h) {
    HeapItem top = h->data[0];
    h->data[0] = h->data[--h->size];
    heapSiftDown(h, 0);
    return top;
}

bool heapEmpty(MinHeap *h) { return h->size == 0; }

void heapFree(MinHeap *h) { free(h->data); free(h); }

/* ---------- Дейкстра ---------- */
/* dist[i] — кратчайшее расстояние от start до i.
 * parent[i] — предыдущая вершина на кратчайшем пути (для восстановления).
 * Возвращает false, если malloc не удался. */
bool dijkstra(Graph *g, int start, int *dist, int *parent) {
    for (int i = 0; i < g->n; i++) {
        dist[i] = INT_MAX;
        parent[i] = -1;
    }
    dist[start] = 0;

    MinHeap *heap = heapCreate(g->n);
    heapPush(heap, 0, start);

    while (!heapEmpty(heap)) {
        HeapItem item = heapPop(heap);
        int u = item.vertex;
        int d = item.dist;

        /* Lazy deletion: если в куче устаревшая запись — пропускаем. */
        if (d > dist[u]) continue;

        for (AdjNode *cur = g->head[u]; cur != NULL; cur = cur->next) {
            int v = cur->to;
            int w = cur->weight;
            if (dist[u] != INT_MAX && dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                parent[v] = u;
                heapPush(heap, dist[v], v);
            }
        }
    }

    heapFree(heap);
    return true;
}

/* Восстановление пути от start до target по массиву parent. */
void printPath(int *parent, int target) {
    if (parent[target] != -1) {
        printPath(parent, parent[target]);
    }
    printf("%d ", target);
}

/* ---------- Беллман-Форд ---------- */
/* Возвращает false, если найден отрицательный цикл. */
bool bellmanFord(Graph *g, int start, int *dist) {
    for (int i = 0; i < g->n; i++) dist[i] = INT_MAX;
    dist[start] = 0;

    /* n-1 итерация релаксации всех рёбер. */
    for (int iter = 0; iter < g->n - 1; iter++) {
        for (int u = 0; u < g->n; u++) {
            if (dist[u] == INT_MAX) continue;
            for (AdjNode *cur = g->head[u]; cur != NULL; cur = cur->next) {
                int v = cur->to;
                int w = cur->weight;
                if (dist[u] + w < dist[v]) {
                    dist[v] = dist[u] + w;
                }
            }
        }
    }

    /* Проверка на отрицательный цикл: ещё одна релаксация. */
    for (int u = 0; u < g->n; u++) {
        if (dist[u] == INT_MAX) continue;
        for (AdjNode *cur = g->head[u]; cur != NULL; cur = cur->next) {
            int v = cur->to;
            int w = cur->weight;
            if (dist[u] + w < dist[v]) {
                return false;   /* отрицательный цикл */
            }
        }
    }
    return true;
}

/* ---------- Пример ---------- */
int main(void) {
    /* Граф: A=0, B=1, C=2, D=3.
     * A→B (1), A→C (4), B→C (2), B→D (6), C→D (3). */
    Graph *g = graphCreate(4);
    graphAddEdge(g, 0, 1, 1);
    graphAddEdge(g, 0, 2, 4);
    graphAddEdge(g, 1, 2, 2);
    graphAddEdge(g, 1, 3, 6);
    graphAddEdge(g, 2, 3, 3);

    int dist[4], parent[4];
    dijkstra(g, 0, dist, parent);

    printf("Дейкстра из A:\n");
    for (int i = 0; i < 4; i++) {
        printf("  до %d: dist=%d, путь: ", i, dist[i]);
        printPath(parent, i);
        printf("\n");
    }

    if (bellmanFord(g, 0, dist)) {
        printf("Беллман-Форд: OK, dist[D]=%d\n", dist[3]);
    } else {
        printf("Беллман-Форд: отрицательный цикл\n");
    }

    graphFree(g);
    return 0;
}
```

### Что важно в реализации

- **Lazy deletion** — если из кучи достали запись с `d > dist[u]`,
  значит, это устаревшая запись (вершину уже обновили через другой
  путь). Пропускаем.
- **`dist[u] != INT_MAX`** — проверка на переполнение. Если `dist[u]`
  бесконечность, `dist[u] + w` переполнится.
- **`parent[]`** — для восстановления пути. Заполняется при каждой
  релаксации.
- **Куча с `realloc`** — начальная ёмкость `n`, но может вырасти
  до `m` (каждое ребро может добавить запись). `realloc` нужен.
- **Беллман-Форд: `n−1` итерация**, потом ещё одна для проверки
  цикла. Если на последней итерации что-то релаксировалось — цикл.
- **`INT_MAX` вместо `INF`** — стандартный приём. Но осторожно
  с переполнением: `INT_MAX + w` даст отрицательное число. Поэтому
  проверяем `dist[u] != INT_MAX` перед сложением.

> **Важно:** в реальном коде вместо `int` для расстояний часто берут
> `long long` — на больших графах сумма весов может переполнить
> `int`. И `INT_MAX` заменяют на что-то вроде `1e18`, чтобы
> сложение не переполнялось.

---

## Итог

- **Кратчайший путь** — минимум суммы весов, а не минимум рёбер.
- **BFS** — для невзвешенного графа, `O(V + E)`.
- **Дейкстра** — для неотрицательных весов. Наивная `O(n²)`, с кучей
  `O((n+m) log n)`. **Не работает** с отрицательными весами.
- **Почему ломается:** фиксирует `dist[u]`, когда берёт `u` из кучи.
  При отрицательных весах потом может найтись более короткий путь.
- **Беллман-Форд** — для любых весов. `O(n·m)`. **Детектит
  отрицательные циклы**.
- **Флойд-Уоршелл** — все пары сразу. `O(n³)`. Для маленьких графов.
- **Правило:** 90% задач — Дейкстра с кучей. Отрицательные веса —
  Беллман-Форд. Все пары и `n` маленькое — Флойд.
- В реальном коде используйте `long long` для расстояний и
  проверяйте переполнение при сложении.
