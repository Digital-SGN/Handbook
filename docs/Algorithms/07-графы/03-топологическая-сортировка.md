# Топологическая сортировка

Представьте, что вы собираете проект из десяти модулей. Модуль `A`
зависит от `B` и `C`, `B` зависит от `D`, `C` тоже зависит от `D`,
`D` ни от чего не зависит. Вопрос: в каком порядке компилировать
модули?

Ответ очевиден: `D`, потом `B` и `C` (в любом порядке), потом `A`.
Но как это **вычислить** для произвольного набора зависимостей?
Именно этим занимается **топологическая сортировка**.

Топосорт — это не «сортировка по значению», как `qsort`. Это
**упорядочивание вершин ориентированного графа** так, чтобы для
каждого ребра `u → v` вершина `u` шла **раньше** `v`. Иными словами:
если `u` должно быть выполнено до `v`, то `u` встанет в результат
раньше.

Где это нужно:

- **Сборка проектов** — `make`, `cargo`, `npm`, `gradle`. Все они
  топологически сортируют граф зависимостей.
- **Планирование задач** — учебный план, где у курсов есть
  prerequisites.
- **Разрешение зависимостей пакетов** — `pip`, `apt`, `npm install`.
- **Планировщики** — порядок выполнения задач в конвейере.
- **Компиляторы** — порядок обхода блоков в графе потока управления.

И ещё одно важное свойство: топосорт **заодно детектит циклы**. Если
в графе есть цикл (A зависит от B, B зависит от A), топосорт
невозможен. И алгоритм это обнаружит.

## Формальная постановка

Дан **ориентированный ациклический граф** (DAG — directed acyclic graph).
Нужно выдать такой линейный порядок вершин, в котором каждое ребро
`u → v` идёт «слева направо»: `u` раньше `v`.

```
    A → B → D
    ↓       ↑
    C ------+
```

Возможные топосортировки:
- `A, C, B, D`
- `A, B, C, D`
- `C, A, B, D`

Все они корректны: для каждого ребра `u → v` вершина `u` идёт раньше
`v`. **Топосортировка не единственна** — если в графе есть
«параллельные» ветки, их можно перемешивать как угодно.

> **Важно:** топосорт существует **только для ациклических графов**.
> Если в графе есть цикл — топосортировки не существует. И оба
> алгоритма, которые мы разберём, это обнаружат.

## Топосорт через DFS

Первый способ — «побочный эффект» DFS. Идея простая: **запускаем DFS,
и когда вершина «закрывается» (все её потомки обработаны) — добавляем
её в результат**. Потом результат разворачиваем.

Почему это работает? В DFS вершина закрывается **после** всех своих
потомков. Значит, если `u → v`, то `v` закроется раньше `u`. Значит,
в списке закрытия `v` будет **раньше** `u`. А нам нужно наоборот —
`u` раньше `v`. Поэтому результат **разворачиваем**.

```text
TOPOSORT_DFS(g):
1  visited ← [false] * n
2  result  ← пустой список
3  for каждой вершины u:
4      if not visited[u]:
5          DFS(u)
6  reverse(result)
7  return result

DFS(u):
1  visited[u] ← true
2  for каждого соседа v вершины u:
3      if not visited[v]:
4          DFS(v)
5  result.append(u)      ← добавляем ПОСЛЕ обхода потомков
```

**Ключевая строка** — `result.append(u)` **после** цикла по соседям.
Это и есть post-order. Если добавить до цикла — получится pre-order,
и топосорт не будет работать.

```
DFS из A:
  A: идём в B
    B: идём в D
      D: соседей нет, append(D)     → result = [D]
    B: append(B)                    → result = [D, B]
  A: идём в C
    C: D уже посещён, append(C)     → result = [D, B, C]
  A: append(A)                      → result = [D, B, C, A]

reverse → [A, C, B, D] 
```

Проверяем: `A → B` — A раньше B. `A → C` — A раньше C.
`B → D` — B раньше D. `C → D` — C раньше D . Работает.

> **Главная мысль:** топосорт через DFS — это **post-order + reverse**.
> Одна строчка в DFS, одна строчка после. Самое короткое решение
> из возможных.

**Сложность:** `O(V + E)`. Каждую вершину и каждое ребро обрабатываем
один раз.

## Топосорт через алгоритм Кана

Второй способ — **алгоритм Кана** (Kahn's algorithm, 1962). Он не
использует DFS вообще, а работает с **входящими степенями**.

Идея: вершина, у которой **нет входящих рёбер** (in-degree = 0), может
быть выполнена **прямо сейчас** — от неё ничего не зависит. Берём её,
добавляем в результат, «удаляем» из графа (уменьшаем in-degree всех
её соседей). Если у соседа in-degree стал 0 — он тоже готов.

1. Считаем `inDegree[v]` для всех вершин.
2. Кладём в очередь все вершины с `inDegree = 0`.
3. Пока очередь не пуста:
   - достаём `u`, добавляем в результат;
   - для каждого соседа `v`: `inDegree[v]--`; если стал 0 — в очередь.
4. Если в результате меньше `n` вершин — в графе есть цикл.

```text
TOPOSORT_KAHN(g):
1  inDegree ← [0] * n
2  for каждого ребра (u, v):
3      inDegree[v]++
4  queue ← все вершины с inDegree = 0
5  result ← пустой список
6  while not queue.empty():
7      u ← queue.pop()
8      result.append(u)
9      for каждого соседа v вершины u:
10         inDegree[v]--
11         if inDegree[v] = 0:
12             queue.push(v)
13 if len(result) < n:
14     return "цикл"
15 return result
```

**Пример** на том же графе:

```
in-degree: A=0, B=1, C=1, D=2
queue: [A]

pop A → result=[A], B.in-- → 0, C.in-- → 0
queue: [B, C]

pop B → result=[A,B], D.in-- → 1
queue: [C]

pop C → result=[A,B,C], D.in-- → 0
queue: [D]

pop D → result=[A,B,C,D]
queue: []

result = [A, B, C, D]
```

> **Главная мысль:** алгоритм Кана — это BFS по «готовым» вершинам.
> Мы не идём вглубь, а **снимаем слои**: сначала все вершины без
> зависимостей, потом те, у кого зависимости только что снялись,
> и так далее.

**Сложность:** `O(V + E)`. Считаем in-degree за один проход, потом
каждую вершину и каждое ребро обрабатываем один раз.

## Детект цикла

Оба алгоритма детектят цикл — но по-разному.

**Алгоритм Кана:** если после обработки в `result` оказалось меньше
`n` вершин — значит, часть вершин застряла в цикле (у них никогда не
станет `in-degree = 0`). Это самый простой способ детекта цикла:
**просто сравнить длину результата с `n`**.

**DFS:** нужны **три цвета** вместо двух:

- **белый** — не посещена;
- **серый** — в текущем стеке рекурсии (мы в неё зашли, но ещё не
  вышли);
- **чёрный** — обработана полностью.

Цикл есть, если при обходе мы наткнулись на **серую** вершину. Это
значит, что мы вернулись в вершину, из которой ещё не вышли, —
то есть нашли цикл.

```text
DFS_CYCLE(u):
1  color[u] ← GRAY
2  for каждого соседа v:
3      if color[v] = GRAY:
4          return "цикл"
5      if color[v] = WHITE:
6          DFS_CYCLE(v)
7  color[u] ← BLACK
```

> **Важно:** для **неориентированного** графа достаточно двух цветов
> (посещена / не посещена) и проверки «не родитель». Для
> **ориентированного** — нужны три цвета. Потому что в орграфе
> «посещённая» вершина может быть как «в стеке» (цикл), так и
> «обработана» (не цикл). Разница принципиальна.

Если цикл нужен не «есть/нет», а **сам цикл** — при DFS сохраняйте
стек рекурсии и при нахождении серой вершины выводите путь от неё
до текущей.

## Сравнение двух подходов

| Критерий | DFS + reverse | Алгоритм Кана |
|----------|---------------|---------------|
| Идея | Post-order + разворот | Снятие слоёв по in-degree |
| Структура данных | Стек (рекурсия) | Очередь |
| Детект цикла | Три цвета | `len(result) < n` |
| Порядок обхода | Не гарантирован | «Слоями», предсказуем |
| Рекурсия | Да (или явный стек) | Нет |
| Сложность | `O(V + E)` | `O(V + E)` |
| Когда выбирать | Уже есть DFS, нужен короткий код | Нужна предсказуемость, нет рекурсии |

**Что выбрать:**

- Если у вас **уже есть DFS** в коде — добавьте post-order, топосорт
  получится «бесплатно».
- Если пишете **с нуля** — алгоритм Кана проще понять и отладить,
  не боится глубокой рекурсии.
- Если нужен **лексикографически минимальный** топосорт — берите Кан
  с приоритетной очередью вместо обычной.
- Если нужен **детект цикла** — Кан проще (сравнение длины), но
  DFS даёт больше информации (можно вывести сам цикл).

> **Главная мысль:** оба алгоритма правильные и `O(V + E)`. Выбор —
> вопрос удобства. В реальном коде чаще встречается Кан: он не
> рекурсивный и даёт предсказуемый порядок.

## Реализация на C

Реализуем оба алгоритма. Граф — список смежности из первой главы.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>

/* ... структуры Graph и AdjNode из первой главы ... */

/* ---------- Очередь для Кана ---------- */
typedef struct {
    int *data;
    int  head, tail, cap;
} Queue;

Queue* queueCreate(int cap) {
    Queue *q = malloc(sizeof(Queue));
    q->data = malloc(cap * sizeof(int));
    q->head = q->tail = 0;
    q->cap = cap;
    return q;
}
void queuePush(Queue *q, int v) { q->data[q->tail++] = v; }
int  queuePop(Queue *q) { return q->data[q->head++]; }
bool queueEmpty(Queue *q) { return q->head == q->tail; }
void queueFree(Queue *q) { free(q->data); free(q); }

/* ---------- Топосорт через DFS ---------- */
/* result заполняется в post-order, потом разворачивается.
 * Возвращает false, если найден цикл. */
static bool dfsTopo(Graph *g, int u, int *color, int *result, int *idx) {
    color[u] = 1;  /* серый — в стеке рекурсии */

    for (AdjNode *cur = g->head[u]; cur != NULL; cur = cur->next) {
        int v = cur->to;
        if (color[v] == 1) return false;        /* нашли цикл */
        if (color[v] == 0 && !dfsTopo(g, v, color, result, idx))
            return false;
    }

    color[u] = 2;              /* чёрный — обработана */
    result[(*idx)++] = u;      /* post-order: добавляем ПОСЛЕ потомков */
    return true;
}

bool topoSortDFS(Graph *g, int *result) {
    int *color = calloc(g->n, sizeof(int));   /* 0=белый, 1=серый, 2=чёрный */
    int idx = 0;

    for (int u = 0; u < g->n; u++) {
        if (color[u] == 0) {
            if (!dfsTopo(g, u, color, result, &idx)) {
                free(color);
                return false;                 /* цикл */
            }
        }
    }
    free(color);

    /* Разворачиваем результат. */
    for (int i = 0, j = idx - 1; i < j; i++, j--) {
        int tmp = result[i]; result[i] = result[j]; result[j] = tmp;
    }
    return true;
}

/* ---------- Топосорт через алгоритм Кана ---------- */
bool topoSortKahn(Graph *g, int *result) {
    int *inDegree = calloc(g->n, sizeof(int));

    /* Считаем входящие степени. */
    for (int u = 0; u < g->n; u++) {
        for (AdjNode *cur = g->head[u]; cur != NULL; cur = cur->next) {
            inDegree[cur->to]++;
        }
    }

    Queue *q = queueCreate(g->n);
    for (int u = 0; u < g->n; u++) {
        if (inDegree[u] == 0) queuePush(q, u);
    }

    int idx = 0;
    while (!queueEmpty(q)) {
        int u = queuePop(q);
        result[idx++] = u;

        for (AdjNode *cur = g->head[u]; cur != NULL; cur = cur->next) {
            int v = cur->to;
            if (--inDegree[v] == 0) {
                queuePush(q, v);
            }
        }
    }

    queueFree(q);
    free(inDegree);

    /* Если обработали не все вершины — есть цикл. */
    return idx == g->n;
}

/* ---------- Пример ---------- */
int main(void) {
    /* Граф: A=0, B=1, C=2, D=3.
     * Рёбра: A→B, A→C, B→D, C→D. */
    Graph *g = graphCreate(4);
    graphAddEdge(g, 0, 1, 0);
    graphAddEdge(g, 0, 2, 0);
    graphAddEdge(g, 1, 3, 0);
    graphAddEdge(g, 2, 3, 0);

    int result[4];

    if (topoSortDFS(g, result)) {
        printf("DFS:  ");
        for (int i = 0; i < 4; i++) printf("%d ", result[i]);
        printf("\n");
    } else {
        printf("DFS: цикл\n");
    }

    if (topoSortKahn(g, result)) {
        printf("Кан:  ");
        for (int i = 0; i < 4; i++) printf("%d ", result[i]);
        printf("\n");
    } else {
        printf("Кан: цикл\n");
    }

    graphFree(g);
    return 0;
}
```

### Что важно в реализации

- **Три цвета в DFS** — обязательно. Двух цветов недостаточно для
  ориентированного графа: «посещённая» вершина может быть как
  в текущем стеке (цикл), так и уже обработанной (не цикл).
- **`result[(*idx)++] = u` после цикла** — это и есть post-order.
  Если поставить до цикла — топосорт не будет работать.
- **Разворот в конце** — обязателен. Post-order даёт обратный порядок.
- **В Кане `--inDegree[v] == 0`** — префиксный декремент, потому что
  нам нужно **новое** значение. Постфиксный `inDegree[v]-- == 0` дал
  бы неверный результат.
- **Проверка `idx == g->n`** — единственный способ детекта цикла
  в Кане. Если вершины остались с ненулевым in-degree — они в цикле.

> **Важно:** в DFS-версии мы обходим **весь** граф в цикле по всем
> вершинам, а не только от одной. Иначе вершины из других компонент
> не попадут в результат. То же самое в Кане — очередь изначально
> содержит **все** вершины с `inDegree = 0`, а не одну.

## Применения

### Сборка проектов

`make` строит граф зависимостей: цель зависит от файлов, файлы — от
других файлов. Топосорт даёт порядок сборки. Если в графе цикл —
`make` выдаёт ошибку «circular dependency».

### Разрешение зависимостей пакетов

`pip install`, `npm install`, `apt install` — все они строят граф
зависимостей пакетов и топологически сортируют его, чтобы ставить
пакеты в правильном порядке. Цикл в зависимостях — ошибка
«dependency cycle».

### Учебный план

Курсы имеют prerequisites. Топосорт даёт порядок, в котором студент
может пройти все курсы. Если есть цикл (курс A требует B, B требует
A) — план невозможен.

### Планировщики задач

В системах вроде Airflow, Luigi, Prefect задачи описываются как DAG.
Топосорт определяет порядок выполнения. Параллельные ветки можно
запускать одновременно.

> **Главная мысль:** везде, где есть «A зависит от B», топосорт даёт
> порядок. И везде, где есть цикл, топосорт его находит — что часто
> важнее самого порядка.

## Итог

- **Топологическая сортировка** — линейный порядок вершин DAG, где
  каждое ребро `u → v` идёт слева направо.
- Существует **только для ациклических графов**. Цикл → топосорта нет.
- **DFS-версия** — post-order + reverse. Одна строчка в DFS, одна
  после. Детект цикла — три цвета (белый/серый/чёрный).
- **Алгоритм Кана** — снятие слоёв по in-degree. Очередь «готовых»
  вершин. Детект цикла — `len(result) < n`.
- Оба — `O(V + E)`. Оба правильные. Выбор — вопрос удобства.
- **Кан** проще и не рекурсивный. **DFS** короче, если DFS уже есть,
  и даёт больше информации о цикле.
- Применения: сборка проектов, зависимости пакетов, учебные планы,
  планировщики задач. Везде, где есть «A зависит от B».
