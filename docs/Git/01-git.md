## 1. Что такое Git и зачем он нужен?

**Git** - это система контроля версий для отслеживания и ведения истории изменений файлов, в вашем проекте. Чаще всего его используют для кода, но можно и для других файлов. Например, для картинок - полезно для дизайнеров.

С помощью Git вы можете **откатить** свой проект до более **старой версии**, **сравнивать**, **анализировать** или **сливать** свои изменения в репозиторий.

**Репозиторием** называют хранилище вашего кода и историю его изменений. Git работает локально и все ваши репозитории хранятся в определенных папках на жестком диске.

Так же ваши репозитории можно хранить и в интернете. Обычно для этого используют три сервиса:
- [**GitHub**](https://github.com/)
- [**Bitbucket**](https://bitbucket.org/)
- [**GitLab**](https://gitlab.com/)

Каждая точка сохранения вашего проекта носит название **коммит** (commit). У каждого коммита есть **уникальный id и комментарий**. Из таких коммитов собирается ветка. 
**Ветка** - это история изменений. У каждой ветки есть свое название. Репозиторий может содержать в себе несколько веток, которые создаются из других веток или вливаются в них.

## Ключевые понятия

| Термин | Что это      |
| :--- | :---           |
| **Репозиторий**       | Папка с проектом под контролем Git |
| **Коммит**            | Снимок изменений с описанием |
| **Ветка (branch)**  | Отдельная линия разработки |
| **Pull Request (PR)** | Запрос на слияние твоей ветки в основную |
| **Merge**             | Слияние веток |


## 2. Установка
Основным интерфейсом для работы с Git является **консоль/терминал**. Это не совсем удобно, тем более для новичков, поэтому есть альтернативы с графическим интерфейсом (кнопками, графиками и т.д.). 
Могу посоветовать эти:
- [**GitHub Desktop**](https://desktop.github.com/download)
- [**Sourcetree**](https://www.sourcetreeapp.com/)
- [**GitKraken**](https://gitkraken.com/)

Для более подробного понимания лучше все же установить консольный Git

### Windows
Проходим по этой [ссылке](https://git-scm.com/install/windows), выбираем под вашу ОС (32 или 64 битную), скачиваем и устанавливаем.

### macOS
Открываем терминал и пишем:

```bash
# Если установлен Homebrew
brew install git

# Если нет, то вводим эту команду. 
git --version

# После этого появится окно, где предложит установить Command Line Tools (CLT).
# Соглашаемся и ждем установки. Вместе с CLT установится и git
```

### Linux
Открываем терминал и вводим следующую команду.

```bash
# Debian или Ubuntu
sudo apt install git

# CentOS
sudo yum install git
```

## 3. Настройка
Вы установили себе Git и можете им пользоваться. Давайте теперь его настроим, чтобы при создании коммита, указывался автор, кто его создал.

Открываем терминал (Linux и macOS) или консоль (Windows) и вводим следующие команды.

**Важно:** вводите данные аккаунта, который вы создали на GitHub, чтобы потом не было проблем с распознаванием коммитов.

```bash
# Установим имя для вашего пользователя
# Вместо <ваше_имя> можно ввести, например, Grisha_Popov
# Кавычки оставляем
git config --global user.name "<ваше_имя>"

# Теперь установим email. Принцип тот же.
git config --global user.email "<адрес_почты@email.com>"
```

## 4. Создание репозитория
Теперь вы готовы к работе с Git локально на компьютере.

Создадим наш первый репозиторий. Для этого пройдите в папку вашего проекта (или можно открыть терминал прямо из папки).

```bash
# Для Linux и macOS путь может выглядеть так /Users/UserName/Desktop/MyProject
# Для Windows например C:\MyProject
cd <путь_к_вашему_проекту>

# Инициализация/создание локального репозитория
git init
```

Теперь Git **отслеживает изменения файлов вашего проекта**

По умолчанию при git init вы находитесь в ветке main (или master в старых версиях Git). 
Работать напрямую в main в командных проектах не принято — обычно под каждую задачу создают отдельную ветку, а потом вливают её в main через Pull Request.

Создать новую ветку и сразу переключиться на неё:
```bash
# Флаг -c это сокращение от --create, то есть создать
git switch -c <имя_ветки>
```

Пример:
```bash
git switch -c feature-login
```
После этого все новые коммиты будут уходить в ветку feature-login, а main останется нетронутым.

Давайте проверим ветки, для этого нужно использовать команду:
```bash
# Только локальные, текущая отмечена *
git branch

# Все ветки, включая удалённые 
git branch -a
```

Теперь перейдем к созданию коммитов:
```bash
# Добавим все файлы проекта в наш будущий коммит
git add .
# Или так
git add --all

# Если хотим добавить конкретный файл то можно так
git add <имя_файла> 

# Теперь создаем commit. Обязательно указываем комментарий
# И не забываем про кавычки
git commit -m "<комментарий>"

# -m это сокращение от --message, то есть «сообщение»
```

Чтобы отправить ваш код на GitHub необходимо создать там новый **репозиторий** (он будет являются удаленным относительно нашего локального) и **связать** его с вашим **локальным**, делается это командой:
```bash
git remote add <псевдоним> <URL_адрес>
```
 **Псевдоним** вашего репозитория это некое короткое имя, чтобы при дальнейших отправках **не писать полностью UR**L, обычно в качестве псевдонима использую **origin**

**Пример**:
```bash
# Cвязывание с репозиторием нашего справочника (псевдоним origin)
git remote add origin https://github.com/Demonrux/Digital-department-handbook
```

После этого вы можете отправлять коммиты на ваш связанный** удаленный репозиторий** GitHub, делается это командой:
```bash
git push <URL_или_псевдоним> <имя_ветки>
```

**Пример**:
```bash
# Отправить изменения в репозиторий нашего проекта (по URL) в ветку main
git push https://github.com/Demonrux/Digital-department-handbook main  

# Или можно по псевдониму (объявили его выше когда связывали - git remote add)
git push origin main   # обращение по псевдониму
```

Также при пуше можно поставить флаг **-u** (сокращение от **--set-upstream**)
Он говорит Git: «запомни, что эта **локальная ветка** связана с вот этой **удалённой веткой**»

```bash
git push -u <URL_или_псевдоним> <имя_ветки>
```
После этого можно писать просто:

```bash
git push
git pull
```

Без указания **псевдонима** (или адреса) и ветки. Git **уже знает**, куда отправлять и откуда забирать


Отлично, вы создали свой первый репозиторий и заполнили его первым коммитом!

## 5. О работе с .gitignore

Файл .gitignore — это текстовый файл, в котором вы перечисляете шаблоны файлов и папок, которые Git не должен отслеживать.

**Ключевой момент**: .gitignore влияет только на неотслеживаемые файлы. Если файл уже был добавлен в репозиторий и закоммичен, просто добавить его в .gitignore недостаточно — Git продолжит его видеть.

То есть с помощью одного небольшого текстового файла можно:
- исключать из коммитов сгенерированные файлы и каталоги сборки;
- не допускать попадания в репозиторий конфиденциальных данных;
- поддерживать репозиторий в чистоте, чтобы в истории были только действительно важные изменения.

Пример типичного .gitignore в корне:

```gitignore
# Игнорируем каталоги сборки
build/
dist/

# Игнорируем временные файлы редакторов
*.swp  
*.tmp  

# Игнорируем логи
logs/
*.log
```

Готовые шаблоны — на [gitignore.io](https://www.toptal.com/developers/gitignore).
Более подробно о работе с .gitignore можно почитать [тут](https://purpleschool.ru/knowledge-base/git/basics/gitignore).

## 6. Справочник по базовым командам и рабочему циклу

### Рабочий цикл (запомни!)

1. `git pull origin main` — подтяни свежие изменения из `main`.
2. `git checkout -b my-branch` — создай ветку для своей задачи.
3. Правь файлы.
4. `git add .` потом создание коммитов `git commit -m "Что сделал"` и после этого  отправка изменений `git push origin my-branch`.
5. Открой Pull Request на GitHub.
6. После ревью — merge, и твоя фича в `main`.

**Золотое правило:** никогда не коммить напрямую в `main`. Только через ветку и PR.

Пример:
```bash
git checkout main
git pull origin main
git switch -c my-branch

# Правишь файлы

git status
git add .
git commit -m "Что сделал"
git push -u origin my-branch

# Дальше открываешь Pull Request на GitHub
```

### Базовые команды

```bash
# Справка по всем командам
git help 

# Настройка (один раз)
git config --global user.name "Твоё Имя"
git config --global user.email "you@example.com"

# Клонирование репозитория
git clone https://github.com/username/repo.git

# Посмотреть статус
git status

# Создать ветку и переключиться на неё
git switch -с <имя_ветки>

# Просмотр веток
# С флагом -a отображаются как локальные, так и удаленные ветки
git branch -a

# Добавить изменения в индекс
git add file.md
git add .           # все файлы

# Коммит
git commit -m "Add feature"

# Отправить на GitHub
git push <URL_или_псевдоним> <имя_ветки>

# Получить последние изменения
git pull <URL_или_псевдоним> <имя_ветки>
```
