## 1. Что такое Markdown и зачем он нужен?

**Markdown** — это удобочитаемый язык разметки, который прозрачно конвертируется в HTML. Его можно открывать и изменять в любом текстовом редакторе. Широко используется для написания документаций и README-файлов.

Главная идея: **обычный текст должен оставаться читаемым, даже без рендеринга**. Сравните:

```text
# Заголовок
Это **важный** текст со [ссылкой](https://example.com).
```

Даже в исходном виде понятно, что тут написано. А после конвертации в HTML мы получим полноценный заголовок, жирный шрифт и кликабельную ссылку.

### Ключевые понятия

| Термин | Что это |
| :--- | :--- |
| **Markdown** | Язык разметки на основе обычного текста |
| **Рендеринг** | Преобразование `.md` в HTML для отображения |
| **CommonMark** | Строгая спецификация Markdown |
| **GFM** | GitHub Flavored Markdown — расширение от GitHub |
| **Диалект** | Вариант Markdown с расширениями (Telegram, Discord и т.д.) |

> **Важно:** Markdown — это не язык программирования. Это просто набор правил, как обычный текст превратить в размеченный.

## 2. Где используется

Markdown вы встретите практически везде, где есть документация:

- **GitHub / GitLab / Bitbucket** — README, комментарии к PR, issues, wiki.
- **Документация** — Дока, MDN, официальные сайты библиотек.
- **Статические генераторы сайтов** — Hugo, Jekyll, Docusaurus, VitePress.
- **Заметки** — Obsidian, Notion (частично), Joplin.
- **Мессенджеры** — Telegram, Discord, Slack (упрощённая версия).
- **Stack Overflow** — редактор вопросов и ответов.

В вашем проекте все `.md` файлы (`01-git.md`, `02-conventional-commits.md`) — это тоже Markdown. Именно поэтому они красиво отображаются на GitHub.

## 3. Базовый синтаксис

### Заголовки

Два стиля записи:

**Через решётки (Atx-style)** — основной способ:

```markdown
# Заголовок 1 уровня
## Заголовок 2 уровня
### Заголовок 3 уровня
#### Заголовок 4 уровня
##### Заголовок 5 уровня
###### Заголовок 6 уровня
```

**Через подчёркивания (Setext-style)** — только для первых двух уровней:

```markdown
Заголовок 1 уровня
==================

Заголовок 2 уровня
------------------
```

> **Совет:** используйте только решётки. Setext-style устарел и плохо читается в исходнике.

### Параграфы и переносы строк

Параграф — это одна или несколько подряд идущих строк, отделённых пустой строкой. Подряд идущие строки **склеиваются в одну**.

Чтобы сделать жёсткий перенос, есть три способа:

```markdown
Привет,
мир!                        <!-- склеится в одну строку -->

Привет,<пробел><пробел>
пробел!                     <!-- перенос через два пробела -->

Привет,\
косая черта!                <!-- перенос через обратную косую -->

Привет,<br>
тег бр-р-р!                 <!-- перенос через HTML-тег -->
```

> **Совет от Сергея Минакова:** не используйте два пробела для переноса — IDE часто стирает trailing whitespace. Лучше `<br>` — он работает везде.

### Выделение текста

```markdown
*Курсив* или _курсив_
**Жирный** или __жирный__
***Жирный курсив*** или ___жирный курсив___
~~Зачёркнутый~~ (только GFM)
```

Результат:

*Курсив* · **Жирный** · ***Оба стиля*** · ~~Зачёркнутый~~

**Экранирование** служебных символов — через обратную косую черту:

```markdown
\*Это не курсив\*
\_И это не курсив\_
\# Это не заголовок
```

### Списки

**Маркированные** — минус, плюс или звёздочка:

```markdown
- Помидор
- Огурец

+ Бублик
+ Ватрушка

* Молоко
* Кефир
```

> Если перед подряд идущими пунктами стоят **разные маркеры**, после конвертации получатся **разные списки**.

**Упорядоченные** — цифры с точкой:

```markdown
1. Хлеб
2. Молоко
3. Помидоры
```

**Ленивая нумерация** — можно везде писать `1.`, Markdown сам пронумерует:

```markdown
1. Хлеб
1. Молоко
1. Помидоры
```

Число перед первым пунктом задаёт начало нумерации. `99.` → 99, 100, 101.

**Вложенность** — отступ табом или пробелами:

```markdown
+ Хлеб
+ Молочные продукты
  1. Кефир
  2. Ряженка

1. Молоко
2. Хлебобулочные изделия
   + Бублик
   + Ватрушка
```

Количество пробелов зависит от длины родительского маркера (`L`):

| Маркер | Длина | Отступ для вложенного |
| :--- | :--- | :--- |
| `+` | 1 | 2–5 пробелов |
| `1.` | 2 | 3–6 пробелов |
| `99.` | 3 | 4–7 пробелов |

### Цитаты

Треугольная скобка `>` в начале строки:

```markdown
> Одна треугольная скобка
превращает в цитату несколько строк,
идущих друг за другом.

> Первая, родительская цитата
> > А это уже вторая,
> > дочерняя цитата
```

Внутри цитаты можно использовать любые блоки — заголовки, списки, код:

```markdown
> # Цитаты великих людей
> Ваша работа заполнит большую часть жизни...
>
> *— Стив Джобс, Речь в Стенфорде*
```

### Горизонтальный разделитель

Три и более дефиса, подчёркивания или звёздочки на одной строке:

```markdown
---

***

_ _ _
```

## 4. Ссылки и изображения

### Ссылки

Три стиля разметки:

**Строчный** — самый частый:

```markdown
Привет, [Дока](https://doka.guide "Энциклопедия про web-dev")!
```

**Справочный** — удобен, когда одна ссылка используется много раз:

```markdown
У [Доки][1] есть свой [репозиторий][repo].

[1]: https://doka.guide "Энциклопедия про web-dev"
[repo]: https://github.com/doka-guide "Репозиторий Доки"
```

**Автоматический** — для URL и email:

```markdown
Заходите на <https://doka.guide>
или пишите на <hi@doka.guide>
```

### Изображения

Синтаксис почти как у ссылок, но с восклицательным знаком в начале:

```markdown
![Одна собака](dog.png "Собака смотрит влево")
```

Справочный стиль:

```markdown
![Одна собака][1]

[1]: dog.png "Собака смотрит влево"
```

### Картинка-ссылка (частый приём в README)

```markdown
[![Логотип](logo.png)](https://example.com)
```

Клик по картинке ведёт на сайт. Так оформляют бейджи и превью видео.

### Проблема со скобками в URL

Если в ссылке есть скобки, Markdown может её неправильно распарсить:

```markdown
[Ковариантность](https://ru.wikipedia.org/wiki/Ковариантность_и_контравариантность_(математика))
```

Выведет «Ковариантность)» — ссылка оборвётся на первой `)`. Решение — обернуть URL в угловые скобки:

```markdown
[Ковариантность](<https://ru.wikipedia.org/wiki/Ковариантность_и_контравариантность_(математика)>)
```

Именно так делает Prettier при форматировании `.md` файлов.

## 5. Исходный код

### Строчный код

Одна-две пары бэктиков:

```markdown
Функция `alert()` вызывает диалоговое окно.
```

### Блок кода

Три и более пар бэктиков. Можно указать язык для подсветки:

````markdown
```c
#include <stdio.h>

int main(void) {
    printf("Hello, world!\n");
    return 0;
}
```
````

Указание языка (`c`, `bash`, `python`, `json`...) не меняет вид в исходнике, но включает подсветку синтаксиса на GitHub и в редакторах.

### Отступ (альтернативный способ)

Таб или 4 пробела перед каждой строкой. Блок нужно отделять пустой строкой:

```markdown
    const a = 1;
    const b = 2;
    (a + b).toString();
```

> В современном Markdown лучше использовать бэктики — они читабельнее и позволяют указать язык.

## 6. Таблицы и списки задач (GFM)

Это расширения GitHub Flavored Markdown — в оригинальном Markdown их нет.

### Таблицы

```markdown
| Место | Участник | Рейтинг |
|-------|----------|---------|
| 1     | Саша     | 118     |
| 2     | Юля      | 92      |
| 3     | Даниил   | 36      |
```

Выравнивание задаётся двоеточиями в разделителе:

```markdown
| Слева | По центру | Справа |
|:------|:---------:|-------:|
| a     | b         | c      |
```

Результат:

| Слева | По центру | Справа |
|:------|:---------:|-------:|
| a     | b         | c      |

Размер ячеек не важен — Markdown выровняет сам:

```markdown
|Место|Участник|Рейтинг|
|-:|:-:|:-|
|1|Саша|118|
```

### Список задач

Маркированный список с чекбоксами `[ ]` и `[x]`:

```markdown
- [x] Выйти на улицу
- [x] Зайти в магазин
- [ ] Купить продукты
  - [x] Молоко
  - [ ] Хлеб
- [ ] Вернуться домой
```

Отрисовывается как интерактивные чекбоксы на GitHub.

## 7. Стандартизация и диалекты

### Проблема стандартизации

У Markdown есть оригинальная спецификация от **Джона Грубера**, но она не описывает многие частные случаи. Из-за этого разные конвертеры работают по-разному.

Чтобы это исправить, сообщество создало **CommonMark** — строгую спецификацию с эталонной реализацией парсера. Большинство современных редакторов и платформ следуют именно ей.

### Диалекты

| Диалект | Где используется | Особенности |
| :--- | :--- | :--- |
| **CommonMark** | База для многих платформ | Строгая спецификация |
| **GFM** | GitHub, GitLab | Таблицы, чекбоксы, зачёркивание, автолинки |
| **Stack Exchange** | Stack Overflow | `[tag:javascript]`, спойлеры `>!` |
| **Telegram / Discord** | Мессенджеры | Только выделение текста, кода и ссылок |

### GFM (GitHub Flavored Markdown)

Расширяет CommonMark:

- **Таблицы** — см. выше.
- **Списки задач** — `- [x]`.
- **Зачёркивание** — `~~текст~~`.
- **Автоссылки** — URL без угловых скобок становится ссылкой.
- **Упоминания** — `@username`, `#123` (issue).

### Stack Exchange Additions

- **Теги:** `[tag:javascript]` → ссылка на вопросы по тегу.
- **Спойлеры:** `>! скрытый текст` → цитата, которая разворачивается по клику.

```markdown
В конце пятого эпизода выясняется, что
>! он его отец.
```

### Мессенджеры (Telegram, Discord)

Упрощённая версия: нет заголовков, списков, таблиц. Есть только:

- `**жирный**`
- `*курсив*` или `_курсив_`
- `__подчёркнутый__`
- `~~зачёркнутый~~`
- `` `код` ``
- `[ссылка](url)`

> Если пишете бота или интеграцию с Telegram — проверьте, какой именно синтаксис поддерживает платформа. Это не полный Markdown.

````markdown
|:----------|----------:|
| ячейка    | ячейка    |

- [x] выполнено
- [ ] не выполнено

---
````

## 9. Частые ошибки и советы

### Топ-5 ошибок новичков

1. **Забыли пустую строку перед списком или кодом.** Markdown не всегда понимает, где заканчивается параграф и начинается блок.
2. **Разные маркеры в одном списке.** `-`, `+`, `*` — это разные списки. Используйте один стиль.
3. **Два пробела для переноса строки.** IDE их стирает. Используйте `<br>`.
4. **Скобки в URL без `<...>`.** Ссылка обрывается на первой `)`. Оборачивайте в `<...>`.
5. **Смешение регистра в заголовках.** Если начали с большой буквы — продолжайте так во всём проекте.

### Стилевые советы

- **Один H1 на документ** — название. Всё остальное — H2/H3.
- **Пустая строка вокруг блоков** (таблиц, кода, цитат) — обязательна.
- **Комментарии в Markdown** делаются через HTML: `<!-- текст -->`. Они не отображаются при рендеринге.
- **Форматируйте файлы.** Prettier автоматически расставляет отступы и оборачивает URL в `<...>`. Подключите его к редактору.
- **Проверяйте рендер.** GitHub показывает Markdown так же, как и в финальном документе. Открывайте предпросмотр (`Ctrl+Shift+V` в VS Code).

### Готовые ресурсы

- [**CommonMark Spec**](https://spec.commonmark.org/) — официальная спецификация.
- [**GitHub Flavored Markdown Spec**](https://github.github.com/gfm/) — спецификация GFM.
- [**Markdown Guide**](https://www.markdownguide.org/) — подробный справочник.
- [**Дока: Markdown**](https://doka.guide/tools/markdown/) — русскоязычный гайд.

## Итог

- **Markdown** — простой язык разметки, который читается в исходнике и рендерится в HTML.
- Базовое: заголовки `#`, выделение `**`/`*`, списки `-`/`1.`, ссылки `[]()`, картинки `![]()`.
- Код: `` `строчный` `` и блок через три бэктика с указанием языка.
- Расширения GFM: таблицы, чекбоксы, зачёркивание.
- **Диалектов много** — GitHub, Telegram, Stack Overflow используют разные подмножества.
- Следите за пустыми строками, единообразием маркеров и экранированием.
- Пишите так, чтобы **исходник был читаемым** — это главная идея Markdown.
